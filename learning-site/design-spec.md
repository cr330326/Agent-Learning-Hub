# Agent Learning Hub · 学习网站设计 Spec

> 这份 spec 是三个设计方向的**唯一共同输入**。三版用同一批真实内容、同一套数据层
> （`data.js`），只换设计逻辑，方便横向对比。

## 1. 这是什么产品

一个**本地运行的单人学习工作台**，不是给外人看的官网。它把散在 `local-courses/`
里 60+ 个仓库、300+ 篇 Markdown 收束成一条可执行的学习路线，并内置阅读器直接读这些
文档。启动方式是 `python3 -m http.server 8765`，只有维护者本人和少数被分享的人会打开。

这一点决定了所有取舍：**它要经得起每天被打开半小时**，而不是「第一眼惊艳、第二次就
嫌吵」。营销站的表达欲在这里是负资产。

## 2. 目标受众与使用场景

单一用户：一位正在系统学习 AI Agent 工程的开发者（仓库维护者本人）。

三种真实场景，权重从高到低：

1. **接着上次读**（每天最高频）— 打开就该知道「我读到哪、下一篇是什么」，两次点击内
   回到正文。阅读器是这个站的主功能，不是附属品。
2. **按主题找资料**（每周若干次）— 「记忆是怎么做的」→ 需要跨 Hello-Agents 第 8 章、
   mem0、claude-mem、Hermes 记忆调研四处横跳。搜索和轨道筛选要够快。
3. **看进度、定计划**（每月若干次）— 9 个 Stage 做到哪了、哪条轨道还是空的。

场景 1 和 2 说明：**信息密度必须高，翻页成本必须低**。首屏塞不下所有东西时，优先给
「继续阅读」和「找得到」，不是给 hero 大字。

## 3. 内容结构（三轨道 × 九阶段 × 三百章）

`local-courses/` 已经重组成三条一级轨道，站点结构必须和它一一对应，不能另起一套：

- **Learning** — 系统课程与教材。Hello-Agents（16 正文 + 12 扩展）、claw0（10 章中文
  讲义）、Easy Agent、easy-learn-ai，以及三本 PDF 教材。
- **AI-Coding** — Coding agent 与 harness。learn-claude-code（20 章）、Claude Code 源码
  逆向分析（13 篇）、OpenClaw 官方指南（16 章 + 附录）、OpenCode 中文实战课、Codex、
  Hermes、CyberClaw、MiMo-Code、Claude 插件生态。
- **Agentic** — 框架、记忆与理论。Learn Harness Engineering（12 讲）、Harness Books
  双册、驾驭工程书（30+ 章分三组）、mem0、LangChain 全家桶、CrewAI、MetaGPT、AutoGPT、
  OpenHands、PI、openworker。

叠在上面的是一条**九阶段路线**（Stage 0 理解 Agent → Stage 8 交付真实 Agent），每阶段
带可勾选任务、明确产出，并链到具体章节。再加**十一级项目阶梯**和**六张速记卡**。

规模：33 门课程卡片、40 个阅读器分组、293 条本地引用。**这是一个密集目录，不是一个
落地页。** 任何让每屏只能放 3 个条目的设计都是错的。

## 4. 情感基调与气质

关键词：**沉稳、可信、耐读、有秩序感**。

它应该像一个用了很久、越用越顺手的工具，而不是一次发布会。允许有一处「值得截图」的
签名细节，但不允许通篇炫技。学习本身已经够累了，界面不该再增加认知负担。

## 5. 输出格式与尺寸

- 桌面网页，截图基准 **1440×900**。
- 必须在 1280 宽可用，1024 以下降为单栏。
- 纯 HTML + CSS + 原生 JS，无构建步骤，`python3 -m http.server` 直开。
- 深浅色不做双主题（本地工具，一套做到位即可）。

## 6. 已知约束

- **数据层不动**：三版共用 `data.js` + `app.js`，只换 `index-*.html` 骨架和 CSS。
  这也意味着三版的内容完全一致，差异 100% 来自设计。
- **可读性硬底线**：正文 ≥14px、标签 ≥12px、正文对比度 ≥4.5:1。三版都要过。
- **必含模块**：轨道总览、九阶段路线（可勾选）、课程网格（带轨道筛选）、项目阶梯、
  速记卡、阅读器（左菜单 + 右正文 + 标记完成 + 上下章）。
- **中文优先**：CJK 一律走系统字（PingFang SC / 思源），Latin 才用 display 字体。
  离线时 Google Fonts 拉不到，必须有可用的系统栈兜底，版式不能塌。

## 7. 图片素材判断（Phase 3.5）

**判定：图片不是这个设计的内容必需品。** 内容是课程目录、章节标题、学习状态，没有
任何一张照片能让信息不丢失——放 stock「灵感图」只会是 slop。所以三版全部走纯
HTML/CSS，不取装饰图。

**具名产品 logo（已解决，2026-08-06）**：卡片点名了 33 个真实项目，实际能取到官方
素材的是 13 个（Claude ×7、OpenAI、OpenCode ×2、LangChain、CrewAI、小米），
覆盖率 39%；claw0、CyberClaw、openworker 这类个人仓库根本没有官方 logo。

先前的顾虑是「39% 覆盖率的 logo 墙看起来像加载失败」。**问题不在覆盖率，在两类标记
被当成两个视觉阶级**——有图的是彩色图形，没图的是空白。解法是让两者共用同一套标牌：

- 同一个 26×26 方框、同样的 1px 描边、同样的**线路色单墨**
- 有官方素材 → 图形标记，走 CSS `mask` 只取 alpha 通道，用 `currentColor` 上色
- 没有素材 → 两字母标记，同框同色同尺寸

单墨还顺手解决了另一个问题：品牌原色（Claude 赤陶、CrewAI 珊瑚红、小米橙、LangChain
浅蓝）直接铺在奶油纸面上会互相打架，转成线路色单墨后整片网格才是一个系统。

这不是妥协，是标牌系统的常规做法——Vignelli 的导视里，图形符号和字母/数字本来就
共用同一个徽章框。差异只是「有些标记是图形、有些是字母」，而不是「有些有、有些没有」。

## 8. 视觉母题（form 推导第五问）

每个方向必须从内容里长出一个别的主题不会有的母题，不许套风格标签：

- 这份内容独有的东西是：**三条并行轨道**、**九级递进**、**300+ 篇可勾选的章节**、
  **「读到哪了」这个状态**。
- 三个方向各选一个母题去发挥（见各自 HTML 顶部注释），共同要求是：母题必须承载真实
  数据，不能只是装饰图形。

## 9. 反 slop 红线

- 禁紫渐变、禁 emoji 当图标、禁圆角卡片 + 左彩色 border、禁 SVG 手画插画。
- 禁「均匀深蓝底 #0D1117 + 通用青紫霓虹」这一种偷懒暗色解。走暗色的方向必须有明确
  的作者意图（光影、色温），不是 SaaS 落地页默认皮肤。
- 不编造数据。所有数字（33 门课、293 条引用、完成度百分比）都由 `data.js` 实时算出。
- 空白靠构图解决，不靠填充。
