## 2. 产品目标

Agent Learning Hub 是一个以实践成果为主线的 Agent 工程学习网站。首版必须做到：

1. 将现有内容组织为一条九阶段学习路线，并允许按四条学习轨道筛选。
2. 让匿名用户在云端完成路线浏览、课程发现和公开内容阅读。
3. 让 GitHub 登录用户跨会话保存进度、收藏、笔记和阶段成果。
4. 让本地用户通过 Docker 使用本机 `local-courses/` 素材库和站内阅读器。
5. 让云端部署不携带、不依赖、不代理第三方本地素材正文。
6. 让素材库更新可检查、可选择、可审计，并保护存在本地改动的嵌套仓库。

## 3. 成功标准

首版成功需同时满足：

- 九阶段、四轨道及全部已策展课程能够通过新内容模型表达。
- 云端在完全不存在 `local-courses/` 的环境中可构建、启动和使用。
- 本地模式可读取白名单内的本地 Markdown/MDX，缺失时回退上游网页。
- 用户状态在重启和重新登录后保持一致。
- 阶段只有在用户提交成果记录并主动确认后才可完成。
- 用户可以导出个人数据并彻底删除账户。
- SQLite 备份可在干净环境恢复。
- 新站通过与现有 `learning-site/` 的核心功能对照验收。

## 4. 用户与权限

### 4.1 用户角色

| 角色       | 身份                      | 主要权限                                                 |
| ---------- | ------------------------- | -------------------------------------------------------- |
| 公开访问者 | 未登录                    | 浏览路线、目录、导览、自有正文、项目阶梯和公开搜索       |
| 云端学习者 | GitHub 登录               | 公开访问能力，以及保存进度、收藏、笔记、成果、导出和删号 |
| 本地学习者 | 本机单用户                | 使用本地资料阅读、搜索及本地学习状态；默认免登录         |
| 管理员     | GitHub 稳定用户 ID 白名单 | 查看内容、素材、备份与部署健康，不得查看他人私人笔记正文 |

### 4.2 访问控制要求

- **AUTH-001** 云端使用 GitHub 登录，仅申请身份识别所需的最低权限。
- **AUTH-002** 任意 GitHub 用户均可创建自己的学习状态。
- **AUTH-003** 管理员身份必须通过稳定的 GitHub 用户 ID 判定，不使用可改名的用户名。
- **AUTH-004** 本地模式默认创建固定单用户身份，并只监听 `127.0.0.1`。
- **AUTH-005** 本地服务若配置为监听局域网或公网地址，必须拒绝免登录启动。
- **AUTH-006** 所有个人数据读写必须按当前用户隔离。
- **AUTH-007** 管理员界面不得返回其他用户的私人笔记正文。

## 5. 产品范围

### 5.1 首版范围

- 首页、九阶段路线、课程目录、课程导览、项目阶梯。
- 自有内容阅读器和本地内容阅读器。
- 策展内容搜索。
- GitHub 登录与本地单用户模式。
- 进度、阶段任务、收藏、私人笔记和阶段成果。
- 个人数据导出与删除账户。
- 素材状态检查、选择性更新、路径审计和重建索引。
- 内容审计、失效链接、备份和部署健康页面。
- 云端与本地 Docker 部署。

### 5.2 明确不在首版范围

- AI 导师、自动问答、自动评分和 AI 成果审核。
- 评论、动态流、排行榜和社交关系。
- 证书、积分、连续打卡和付费系统。
- 在线 CMS 或网站内课程投稿表单。
- 云端抓取、代理、缓存或重新托管第三方正文。
- 自动处理有本地修改或发生分叉的嵌套 Git 仓库。

## 6. 信息架构与导航规格

### 6.1 学习结构

- **IA-001** 产品主导航必须以九阶段学习路线为核心。
- **IA-002** Learning、AICoding、Agentic、Application 四条轨道仅用于分类和筛选，不替代阶段顺序。
- **IA-003** 每个阶段必须包含学习目标、维护者讲解、精选资料、实践任务、验收产物和完成状态。
- **IA-004** 每个学习条目必须具有稳定且在云端、本地一致的 ID。
- **IA-005** 课程数量、章节数量和路径命中统计必须由脚本生成，不得手工写死在 README。

### 6.2 页面要求

- **PAGE-001** 首页应解释产品定位、九阶段路线、双运行模式和继续学习入口。
- **PAGE-002** 路线页应显示九阶段顺序、阶段目标、完成情况和轨道分布。
- **PAGE-003** 课程目录应支持按阶段、轨道、标签和访问方式筛选。
- **PAGE-004** 课程导览页应显示维护者摘要、学习目标、来源、作者、许可证、访问方式和相关阶段。
- **PAGE-005** 项目阶梯应展示各阶段的实践任务和预期成果。
- **PAGE-006** 登录后学习面板应显示继续阅读、总体进度、收藏、笔记和阶段成果。
- **PAGE-007** 页面必须清楚标记当前运行模式以及内容的访问类型：站内、上游网页、本地可读或不可用。
- **PAGE-008** 手机端必须支持路线浏览、搜索、阅读、笔记、进度和成果流程。
- **PAGE-009** 列出目录条目的页面（课程目录、搜索结果）必须分页，并只解析当前页条目；不得一次渲染全部目录。分页状态必须体现在 URL 中，便于分享和回退。
- **PAGE-010** 窄屏隐藏主导航时必须提供等价的替代导航，不得出现没有任何站内导航的视口。
- **PAGE-011** 面向用户的界面不得直接显示 schema 枚举值（如 `local-preferred`、`third-party`）或导入占位值（如 `Unknown`）；必须映射为中文标签或明确的“待补/待确认”表述。
- **PAGE-012** 概览类数字（如首页目录规模）必须自洽：分项之和等于总数，或明确说明分项不完备。
- **PAGE-013** 筛选与查询参数必须先对照目录中真实存在的值校验，不匹配时按未传处理；不得据此清空结果，也不得把原始参数值回显到页面上。可选值列表本身也要遵守 PAGE-011，不暴露导入记账标签。
- **PAGE-014** 横向滚动的容器（窄屏导航条、路线图）必须有可见的溢出提示，不能只靠被裁切的文字表示“右边还有内容”。
- **PAGE-015** 顶部导航中的身份入口必须与当前运行模式一致：Local Mode 已自动签入固定单用户，不得提示“登录”。
- **PAGE-016** 不可撤销的个人数据操作必须在视觉上与同一区域内的可逆操作分离，并保留二次确认。
- **PAGE-017** 路线页必须显示每个阶段的完成情况（已勾选动作数与是否已交成果），而不是只显示静态计数。进度不得等同于完成：动作全部勾选只能显示为“待交成果”，阶段完成仍以 STATE-005 的成果确认为准。
- **PAGE-018** 实践动作必须能在阶段页就地勾选并即时保存，不得要求用户离开阶段页去别处记录刚刚做完的事。
- **PAGE-019** 依赖个人状态的控件在未认证时整块不渲染，并给出一句说明；状态快照到达前不得先渲染占位数值再跳变。一个页面对 `/api/state` 只取一次快照，列表中的每一行共享它。

## 7. 内容目录规格

### 7.1 内容来源

- **CAT-001** 公开课程、阶段、项目任务和自有文章必须存放在 Git 管理的 Markdown、MDX 或结构化清单中。
- **CAT-002** SQLite 不得作为公开课程内容的主存储。
- **CAT-003** 内容目录必须在构建和 CI 中通过 schema 校验。
- **CAT-004** `learning-site/data.js` 中现有阶段和课程必须能够无损转换到新内容目录。
- **CAT-005** 第三方学习条目必须记录 `sourceUrl`、作者和许可证状态。
- **CAT-006** `localPath` 必须是可选字段，且只能用于本地解析。
- **CAT-007** 内容审计必须报告重复 ID、无效阶段、缺少来源、未知许可证、失效本地路径和无引用条目。

### 7.2 最小内容结构

```yaml
id: string
title: string
track: learning | aicoding | agentic | application
stageIds: string[]
summary: string
learningGoals: string[]
sourceUrl: string | null
localPath: string | null
accessPolicy: owned | upstream-only | local-preferred | unavailable
author: string
license: string
tags: string[]
lastReviewedAt: date
```

附加约束：

- `id` 在整个目录中唯一，发布后不可随意变更。
- 第三方条目的 `sourceUrl` 不得为空。
- `stageIds` 中每个值必须指向存在的阶段。
- 只有项目自有或明确获准发布的内容可使用 `owned`。
- 未知许可证不得被解释为允许转载。

## 8. 内容解析规格

### 8.1 统一解析结果

Content Resolver 必须返回以下结果之一：

```ts
type ResolvedContent =
  | { type: "internal-mdx"; href: string }
  | { type: "local-document"; href: string }
  | { type: "external-link"; href: string }
  | { type: "unavailable"; reason: string };
```

### 8.2 云端解析

- **RES-001** 自有 Markdown/MDX 在云端解析为站内阅读地址。
- **RES-002** 第三方资料在云端解析为原始上游网页地址。
- **RES-003** 云端代码不得读取、探测或假设存在 `local-courses/`。
- **RES-004** 云端不得提供任意 URL 的服务端抓取或代理接口。

### 8.3 本地解析

- **RES-005** 白名单内且实际存在的本地文件应解析为站内本地阅读地址。
- **RES-006** 本地文件不存在时，有上游地址的条目必须回退为 `external-link`。
- **RES-007** 本地文件不存在且无合法上游地址时返回 `unavailable`，页面应显示原因。
- **RES-008** 解析后的文件路径必须位于配置的只读挂载根目录内。
- **RES-009** 绝对路径、空字节、符号链接逃逸及 `..` 路径穿越必须被拒绝。
- **RES-010** 云端与本地 adapter 必须实现同一个 Content Resolver interface。

## 9. 阅读器规格

- **READ-001** 阅读器支持 Markdown、GFM 表格、代码块、图片、标题目录和上下章导航。
- **READ-002** 阅读器保存并恢复最近阅读位置。
- **READ-003** 阅读位置变化不得自动将条目标记为完成。
- **READ-004** Markdown/MDX 渲染必须采用组件和标签白名单。
- **READ-005** 禁止脚本、事件属性、任意 iframe 和可执行 MDX JavaScript。
- **READ-006** 无法安全渲染的本地内容应提供纯源码视图和上游网页链接。
- **READ-007** 图片路径必须经过与文档路径相同的根目录约束。
- **READ-008** 本地素材目录必须以只读方式挂载，阅读器不得修改素材文件。
- **READ-009** 第三方素材普遍在 Markdown 中混用排版 HTML（居中容器、徽章、`<br>`、表格、`<details>`）。阅读器必须按 READ-004 的白名单保留这类结构，而不是把标签转义成可见文本；`&emsp;` 等有效字符实体必须原样输出。
- **READ-010** 未在课程条目中声明的图片路径必须被丢弃，不得渲染为损坏图片。放宽图片 allowlist 属于安全边界变更，需先更新 ADR。
- **READ-011** 阅读器目录（TOC）必须与正文并列显示且可跟随滚动；长目录内部滚动，不得把正文挤到不可读的宽度。
- **READ-012** 上下章导航必须是显式控件，不能只提供章节列表；首章无上一章、末章无下一章，且两端不得指向不存在的章节。
- **READ-013** 正文中的相对链接是相对于素材文件的，必须先按当前文档所在目录解析：命中允许章节时改写为站内阅读地址；未命中时降级为纯文本。任何情况下都不得输出会解析到阅读器路由下的相对地址（例如 `./docs/ch1.md`），那必然是 404。
- **READ-014** 允许章节由课程条目自身声明；条目未声明的素材文件不可读，界面也不得给出指向它的可点击入口。

## 10. 学习状态规格

### 10.1 状态模型

学习条目状态为：

```text
not_started -> in_progress -> completed
```

- **STATE-001** 用户打开站内正文或点击外部资料时，可将条目标记为 `in_progress`。
- **STATE-002** 条目只能由用户主动操作标记为 `completed`。
- **STATE-003** 用户可将已完成条目改回进行中或未开始。
- **STATE-004** 阶段普通任务可以逐项勾选。
- **STATE-005** 阶段必须至少关联一条成果记录，并由用户主动确认后才可完成。
- **STATE-006** 成果记录支持 GitHub 仓库、演示链接或 Markdown 学习总结。
- **STATE-007** 用户可收藏或取消收藏学习条目。
- **STATE-008** 用户可为条目或阶段创建、编辑和删除私人 Markdown 笔记。
- **STATE-009** 学习面板必须提供继续阅读入口和最近活动。
- **STATE-010** 云端用户状态在不同会话中保持一致。
- **STATE-011** 本地用户状态在容器重启后保持一致。

### 10.2 数据表边界

SQLite 至少保存：

| 数据域             | 建议表                          |
| ------------------ | ------------------------------- |
| 身份与会话         | `users`, `accounts`, `sessions` |
| 条目进度与阅读位置 | `item_progress`                 |
| 阶段任务           | `stage_task_progress`           |
| 私人笔记           | `notes`                         |
| 收藏               | `bookmarks`                     |
| 阶段成果           | `stage_outcomes`                |
| 运营聚合           | `operational_metrics`           |

数据库必须使用迁移管理。删除用户时，其个人状态必须级联删除。`operational_metrics`
只能保存按时间桶聚合的事件类型、固定范围、结果和数量；不得关联用户 ID、IP、Cookie、
查询参数、笔记正文、路径参数或秘密，并应有有限保留期。

## 11. 搜索规格

- **SEARCH-001** 云端搜索索引阶段、课程元数据、自有正文和项目内容。
- **SEARCH-002** 本地模式额外索引内容目录白名单内的本地章节。
- **SEARCH-003** 搜索不得递归扫描整个 `local-courses/`。
- **SEARCH-004** 搜索结果应标记内容类型、阶段、轨道及访问方式。
- **SEARCH-005** 搜索结果必须遵循 Content Resolver 的当前解析结果。
- **SEARCH-006** 内容或本地素材更新后，索引能够重建或增量更新。
- **SEARCH-007** 搜索索引不得包含私人笔记正文。
- **SEARCH-008** 同一份可打开的文档在结果列表中只能出现一次。旧站导入把每个上游章节文件都变成了独立课程条目，其唯一 reference 与条目同名，因此单章条目的正文必须并入条目本身检索；只有多章条目才额外产出逐章结果。
- **SEARCH-009** 每条结果必须给出可区分的定位信息：有关联阶段时显示阶段，否则显示所属合集。不得让整页结果落到同一句占位文案上。

## 12. 素材新鲜度规格

- **MAT-001** 网站进程只读取素材状态快照，不直接执行嵌套仓库更新。
- **MAT-002** 宿主机命令必须支持 `check`、单课程 `update`、`audit` 和 `reindex`。
- **MAT-003** `check` 必须区分最新、落后、分叉、本地修改和检查失败。
- **MAT-004** `update` 一次只处理一个明确课程 ID。
- **MAT-005** 更新只允许 fast-forward；非 fast-forward 情况必须停止并报告。
- **MAT-006** 有已追踪本地修改的仓库必须拒绝自动更新。
- **MAT-007** 更新成功后必须执行路径审计并刷新搜索索引。
- **MAT-008** 操作应输出机器可读结果和便于人工查看的摘要。
- **MAT-009** 素材状态快照不得包含 Git 凭据或其他秘密信息。

## 13. 数据导出与删除规格

- **DATA-001** 用户可导出自己的资料进度、阶段任务、收藏、成果和笔记。
- **DATA-002** 导出至少提供结构化 JSON；笔记内容还应可作为 Markdown 使用。
- **DATA-003** 导出文件不得包含其他用户数据、会话密钥或 OAuth Token。
- **DATA-004** 删除账户前必须要求明确确认。
- **DATA-005** 删除完成后，身份、会话和全部个人学习状态必须被删除。
- **DATA-006** 删除账户不修改 Git 管理的公开内容。

## 14. 管理与健康规格

- **ADMIN-001** 管理员可查看内容 schema 和引用审计结果。
- **ADMIN-002** 管理员可查看素材最新、落后、分叉、本地修改和失败状态。
- **ADMIN-003** 管理员可查看失效上游链接及最近检查时间。
- **ADMIN-004** 管理员可查看数据库、备份和部署版本健康状态。
- **ADMIN-005** 访问统计只能提供不关联个人身份的汇总。
- **ADMIN-006** 管理操作和健康页面不得暴露环境变量、Token、数据库文件或服务器绝对路径。

## 15. 部署规格

### 15.1 通用要求

- **DEPLOY-001** 云端和本地使用同一应用代码、镜像、课程 ID、内容 schema 和学习状态模型。
- **DEPLOY-002** 镜像使用多阶段构建，不包含开发依赖、Git 凭据或本地素材库。
- **DEPLOY-003** Compose 提供基础配置以及云端、本地覆盖配置。
- **DEPLOY-004** 应用必须提供存活和就绪健康检查。
- **DEPLOY-005** 生产部署必须使用固定版本标签，不直接使用 `latest`。

### 15.2 云端模式

- **DEPLOY-006** `DEPLOYMENT_MODE=cloud` 时启用 GitHub 登录。
- **DEPLOY-007** SQLite 数据库位于服务器持久化卷。
- **DEPLOY-008** 云端启动不得要求挂载 `local-courses/`。
- **DEPLOY-009** 云端通过反向代理和 HTTPS 对外服务。

### 15.3 本地模式

- **DEPLOY-010** `DEPLOYMENT_MODE=local` 时默认启用本地单用户身份。
- **DEPLOY-011** `local-courses/` 以只读卷挂载。
- **DEPLOY-012** SQLite 位于本机持久化数据目录。
- **DEPLOY-013** 默认端口只绑定 `127.0.0.1`。
- **DEPLOY-014** 已存在的本地资料应可在断网时阅读和搜索。
- **DEPLOY-015** Docker 入口必须可复现地选择 Local、Cloud 或已发布镜像模式，并在启动后验证健康接口；Local Mode 不得被该入口暴露到非回环地址。

## 16. 安全、隐私和可靠性

### 16.1 安全

- **SEC-001** 所有输入、Markdown、URL 和本地路径均需验证。
- **SEC-002** 用户生成的 Markdown 不得执行脚本或任意 MDX 代码。
- **SEC-003** 登录、笔记、导出和删除接口必须具备 CSRF、防滥用和合理频率限制。
- **SEC-004** 会话 Cookie 在生产环境使用 Secure、HttpOnly 和适当 SameSite 策略。
- **SEC-005** 日志不得记录 OAuth Token、会话密钥、笔记正文和数据库连接秘密。

### 16.2 隐私

- **PRIV-001** 只保存 GitHub 身份所需的最少字段。
- **PRIV-002** GitHub Token 不得用于身份登录之外的用途。
- **PRIV-003** 不接入广告型或跨站追踪。
- **PRIV-004** 私人笔记默认仅创建者可见。

### 16.3 SQLite 与备份

- **OPS-001** SQLite、WAL 和共享内存文件必须位于同一主机的持久化磁盘。
- **OPS-002** 启用 WAL 前必须验证运行时 SQLite 版本包含已知 WAL-reset 问题修复。
- **OPS-003** 每日创建一致性备份，并将加密副本保存到服务器之外。
- **OPS-004** 保留最近 7 个每日备份和最近 3 个每周备份。
- **OPS-005** 每次生产升级前创建额外快照。
- **OPS-006** 必须记录并定期执行干净环境恢复演练。

## 17. 可用性与质量要求

- **NFR-001** 桌面和手机端均可完成核心学习流程。
- **NFR-002** 键盘可访问主要导航、筛选、阅读器和表单操作。
- **NFR-003** 交互控件具有可识别标签，正文、焦点和状态颜色满足基本无障碍对比要求。
- **NFR-004** 内容页面在 JavaScript 尚未完成加载时仍应提供可理解的主体信息。
- **NFR-005** 空状态、无结果、内容缺失、上游失效和无网络状态应提供明确恢复建议。
- **NFR-006** 类型检查、格式检查、单元测试、集成测试和生产构建必须进入 CI。
- **NFR-007** 关键流程必须有端到端测试：匿名浏览、登录保存状态、本地阅读、数据导出和删号。
- **NFR-008** 运行错误、登录失败、数据库健康、备份和内容审计结果必须可观测。
- **NFR-009** 开发服务必须能通过运行手册给出的回环地址（`127.0.0.1` 与 `localhost`）正常 hydration；任一地址无法加载客户端资源都视为缺陷，因为 Local Mode 的免登录身份只对回环地址成立。
- **NFR-010** 界面走查必须可重复执行：在 desktop/tablet/mobile 三档抓取全页截图，并对 HTTP 错误、横向溢出、异常页面高度和控制台报错给出非零退出。该命令依赖运行中的服务，不进入 `npm run check`。
- **NFR-011** 功能回归必须可重复执行且真实点击：遍历站内链接、翻页、筛选、章节导航和学习状态写入/读取/删除，而不是只检查页面能否打开。脚本必须识别运行模式，对该模式不具备的能力断言其正确回退（云端匿名访问被拒、本地素材不出正文），而不是记为失败。

## 18. 验收场景

### AC-01 云端无本地素材运行

**给定** 构建环境中不存在 `local-courses/`  
**当** 构建并以 cloud 模式启动应用  
**那么** 构建和启动成功，公开页面可访问，第三方条目显示上游链接且没有本地文件请求。

### AC-02 本地资料优先与回退

**给定** 应用以 local 模式启动，素材目录只读挂载  
**当** 用户打开一个有本地文件的第三方条目  
**那么** 条目在站内阅读器打开；当文件缺失时，同一条目回退到上游网页。

### AC-03 路径穿越防护

**给定** 一个包含 `..`、绝对路径或逃逸符号链接的本地路径  
**当** 阅读器尝试解析该路径  
**那么** 请求被拒绝，不返回挂载根目录外的文件内容。

### AC-04 学习进度保持

**给定** GitHub 用户已登录  
**当** 用户更新进度、收藏、笔记和阅读位置后重新登录  
**那么** 所有状态按用户正确恢复，且其他用户无法访问这些数据。

### AC-05 阶段完成约束

**给定** 用户已完成阶段中的普通任务，但尚未提交成果  
**当** 用户尝试完成阶段  
**那么** 系统拒绝完成并提示添加成果；添加成果并主动确认后阶段才完成。

### AC-06 个人数据生命周期

**给定** 用户已经产生个人学习数据  
**当** 用户导出数据  
**那么** 导出包含其进度、任务、收藏、成果和笔记，不包含秘密或他人数据；当用户确认删号后，全部个人记录被级联删除。

### AC-07 素材更新保护

**给定** 某嵌套仓库存在本地追踪修改或与上游分叉  
**当** 用户执行单课程更新  
**那么** 更新被拒绝并报告原因；干净且可 fast-forward 的仓库可更新，随后运行审计和索引刷新。

### AC-08 移动端完整流程

**给定** 常见手机宽度  
**当** 用户选择阶段、搜索课程、阅读正文、写笔记并提交成果  
**那么** 全流程无需切换到桌面端即可完成。

### AC-09 备份恢复

**给定** 一份生产兼容的一致性备份  
**当** 在干净服务器恢复数据库并启动相同版本应用  
**那么** 用户身份关联和学习状态完整可读，健康检查通过。

### AC-10 旧站核心能力对等

**给定** 现有 `learning-site/` 的路线、目录、进度和阅读器能力清单  
**当** 执行新旧功能对照验收  
**那么** 新站覆盖所有被标记为首版必需的能力，未覆盖项已有明确迁移决定。

## 19. 需求追踪规则

- 每个实施任务必须引用一个或多个需求 ID 或验收场景。
- 每个需求至少应由一个任务实现，并由自动测试、人工验收或运维演练验证。
- 变更需求时，必须同步更新 [tasks.md](./tasks.md) 中的任务和追踪表。
- 若变更涉及运行模式、内容归属或数据库边界，应先新增或修订 ADR。
