# Agent Learning Hub 产品规格说明

**版本**：1.1（2026-09-18 按现役代码复核；1.0 为 2026-08-09 实施基线）
**配套**：[技术方案](./plan.md) · [任务与完成度](./tasks.md) · [架构决策](../adr/)

## 1. 文档目的

本文定义可测试的产品需求（带需求 ID）和验收场景，是开发、测试和上线验收的依据。需求本身不代表已完成：完成状态、证据和阻塞只记录在 [tasks.md](./tasks.md)，架构与运行边界见 [plan.md](./plan.md)。

变更规则见第 19 节。涉及运行模式、内容归属、身份或数据库边界的变更，先改 ADR。

## 2. 产品目标

Agent Learning Hub 是以实践成果为主线的 Agent 工程学习网站。首版必须做到：

1. 用九阶段路线组织内容，并可按四条学习轨道筛选。
2. 匿名用户在云端完成路线浏览、课程发现和公开内容阅读。
3. GitHub 登录用户跨会话保存进度、收藏、笔记和阶段成果。
4. 本地用户在本机使用 `local-courses/` 素材库和站内阅读器。
5. 云端部署不携带、不依赖、不代理第三方本地素材正文。
6. 素材库变化可检查、可选择、可审计，并保护有本地改动的嵌套仓库。

## 3. 成功标准

- 九阶段、四轨道和全部已策展课程都能用内容模型表达。
- 云端在完全没有 `local-courses/` 的环境中可构建、启动和使用。
- 本地模式可读白名单内的本地 Markdown，缺失时回退上游网页。
- 用户状态在重启和重新登录后保持一致。
- 阶段只有在用户提交成果并主动确认后才算完成。
- 用户可以导出个人数据并彻底删除账户。
- SQLite 备份可在干净环境恢复。
- 新站通过与旧站 `learning-site/` 的核心功能对照验收。

## 4. 用户与权限

### 4.1 用户角色

| 角色       | 身份                      | 主要权限                                                 |
| ---------- | ------------------------- | -------------------------------------------------------- |
| 公开访问者 | 未登录                    | 浏览路线、目录、导览、自有正文、项目阶梯和公开搜索       |
| 云端学习者 | GitHub 登录               | 公开访问能力，外加保存进度、收藏、笔记、成果、导出和删号 |
| 本地学习者 | 本机固定单用户            | 本地素材阅读与搜索、本地学习状态；免登录                 |
| 管理员     | GitHub 稳定用户 ID 白名单 | 查看内容、素材、备份与部署健康；不得查看他人笔记正文     |

### 4.2 访问控制

- **AUTH-001** 云端使用 GitHub 登录，只申请身份识别所需的最低权限。
- **AUTH-002** 任意 GitHub 用户都可以创建自己的学习状态。
- **AUTH-003** 管理员按稳定的 GitHub 用户 ID 判定，不用可改名的用户名。
- **AUTH-004** 本地模式默认使用固定单用户身份，只监听 `127.0.0.1`。
- **AUTH-005** 本地服务配置为监听局域网或公网地址时，必须拒绝免登录启动。
- **AUTH-006** 所有个人数据读写按当前用户隔离。
- **AUTH-007** 管理员界面不得返回其他用户的私人笔记正文。

## 5. 产品范围

### 5.1 首版范围

- 首页、九阶段路线、课程目录、课程导览、项目阶梯。
- 自有内容与本地素材阅读器；策展内容搜索。
- GitHub 登录与本地单用户模式。
- 进度、阶段任务、收藏、私人笔记、阶段成果；个人数据导出与删除账户。
- 素材状态检查、单课程更新、路径审计、目录漂移对账与重建索引。
- 内容审计、备份与部署健康页面；云端与本地 Docker 部署。

### 5.2 明确不做

- AI 导师、自动问答、自动评分和 AI 成果审核。
- 评论、动态流、排行榜和社交关系。
- 证书、积分、连续打卡和付费系统。
- 在线 CMS 或站内投稿表单。
- 云端抓取、代理、缓存或重新托管第三方正文。
- 自动处理有本地修改或已分叉的嵌套 Git 仓库。

## 6. 信息架构与页面

### 6.1 学习结构

- **IA-001** 主导航以九阶段路线为核心。
- **IA-002** Learning、AICoding、Agentic、Application 四条轨道只用于分类和筛选，不替代阶段顺序。
- **IA-003** 每个阶段包含学习目标、维护者讲解、精选资料、实践任务、验收产物和完成状态。
- **IA-004** 每个学习条目有稳定 ID，且云端、本地一致；已发布的 ID 不得失效（退场条目见 CAT-008）。
- **IA-005** 课程数量、章节数量和路径命中统计由脚本或页面实时生成，不得手工写死在 README 等文档中。

### 6.2 页面要求

- **PAGE-001** 首页说明产品定位、九阶段路线、双运行模式，并提供继续学习入口。
- **PAGE-002** 路线页显示九阶段顺序、阶段目标、完成情况和轨道分布。
- **PAGE-003** 课程目录支持按阶段、轨道、标签和访问方式筛选。
- **PAGE-004** 课程导览页显示维护者摘要、学习目标、来源、作者、许可证、访问方式和相关阶段。
- **PAGE-005** 项目阶梯展示各阶段的实践任务和预期成果。
- **PAGE-006** 学习面板显示继续阅读、总体进度、收藏、笔记和阶段成果。
- **PAGE-007** 页面清楚标记当前运行模式，以及内容的访问类型：站内、上游网页、本地可读或不可用。
- **PAGE-008** 手机端支持路线浏览、搜索、阅读、笔记、进度和成果流程。
- **PAGE-009** 列出目录条目的页面（课程目录、搜索结果）必须分页，只解析当前页条目；分页状态写入 URL。
- **PAGE-010** 窄屏隐藏主导航时必须提供等价的替代导航，任何视口都有站内导航。
- **PAGE-011** 界面不得直接显示 schema 枚举值（如 `local-preferred`）或导入占位值（如 `Unknown`），必须映射为中文标签或"待补/待确认"。
- **PAGE-012** 概览数字必须自洽：分项之和等于总数，或明确说明分项不完备。
- **PAGE-013** 筛选与查询参数先对照目录中真实存在的值校验，不匹配按未传处理；不得因此清空结果，不得回显原始参数。可选值列表同样遵守 PAGE-011。
- **PAGE-014** 横向滚动容器（窄屏导航条、路线图）必须有可见的溢出提示。
- **PAGE-015** 顶部导航的身份入口与运行模式一致：本地模式已自动签入，不得提示"登录"。
- **PAGE-016** 不可撤销的个人数据操作在视觉上与可逆操作分离，并保留二次确认。
- **PAGE-017** 路线页显示每个阶段的完成情况（已勾选动作数、是否已交成果）。动作全勾只能显示"待交成果"，阶段完成以 STATE-005 为准。
- **PAGE-018** 实践动作能在阶段页就地勾选并即时保存。
- **PAGE-019** 依赖个人状态的控件在未认证时整块不渲染并给出说明；快照到达前不先渲染占位数值。一个页面只取一次状态快照，列表各行共享。

## 7. 内容目录规格

### 7.1 内容来源

- **CAT-001** 公开课程、阶段、项目任务和自有文章存放在 Git 管理的 Markdown 或结构化清单中。
- **CAT-002** SQLite 不作为公开课程内容的主存储。
- **CAT-003** 内容目录在构建和 CI 中通过 schema 校验。
- **CAT-004** 旧站 `learning-site/data.js` 的阶段和课程无损迁移到新目录。（已于 2026-08-09 完成；此后目录由人手维护，转换器仅作溯源保留，见 [ADR 0006](../adr/0006-catalog-is-hand-maintained.md)。）
- **CAT-005** 第三方条目记录作者、许可证状态和上游地址（`sourceUrl`）。
- **CAT-006** `localPath` 为可选字段，只用于本地解析。
- **CAT-007** 内容审计报告重复 ID、无效阶段、缺少来源、未知许可证、失效本地路径和无引用条目。
- **CAT-008** 同一份本地素材正文只能被一个未退场条目声明（[ADR 0008](../adr/0008-chapter-content-has-a-single-owner.md)）。条目退场必须携带 `redirect`，旧 ID 转发到拥有者而不是 404。重复归属和无效 redirect 属于 schema 级错误，违反时构建、审计和启动全部失败。

### 7.2 学习条目的数据契约

可执行契约是 [`code/modules/catalog/content-schema.ts`](../../code/modules/catalog/content-schema.ts)（Zod，TypeScript 类型由它推导）。核心字段：

| 字段                                          | 含义                                                          |
| --------------------------------------------- | ------------------------------------------------------------- |
| `id`                                          | 全局唯一的小写 kebab-case，发布后不可变更                     |
| `title`、`summary`、`learningGoals`           | 标题、摘要、学习目标                                          |
| `track`、`stageIds`                           | 所属轨道；关联阶段（每个值必须指向存在的阶段）                |
| `accessPolicy`                                | `owned` / `upstream-only` / `local-preferred` / `unavailable` |
| `publicationRights`                           | `project-owned` / `republication-authorized` / `third-party`  |
| `author`、`license`、`licenseStatus`          | 作者、许可证及其是否已确认（`known` / `unknown`）             |
| `sourceUrl`、`localPath`、`references`        | 上游地址、本地主文档、附加章节与入口                          |
| `tags`、`lastReviewedAt`、`unavailableReason` | 标签、最近复核日期、不可用原因                                |
| `redirect`（可选）                            | `{ itemId, chapter? }`，标记退场条目并指向拥有者              |

附加约束：

- 只有项目自有或明确获准发布、且许可证已知的内容可以使用 `owned`。
- 第三方条目不得使用 `owned`；未知许可证不得被解释为允许转载。
- `local-preferred` 需要合法的相对本地路径；`upstream-only` 不带本地路径；`unavailable` 不得伪造可访问地址。
- 退场条目不出现在目录、搜索和计数中，但仍可按 ID 找到以便转发。

## 8. 内容解析规格

### 8.1 统一解析结果

Content Resolver 对每个条目返回以下四种结果之一，并附带面向用户的动作文案：

```ts
type ResolvedContent =
  | { kind: "internal-mdx"; href: string; label: string } // 在站内阅读
  | { kind: "local-document"; href: string; label: string } // 在站内阅读（本地）
  | { kind: "external-link"; href: string; label: string } // 打开上游
  | { kind: "unavailable"; reason: string; label: string }; // 暂不可用
```

### 8.2 云端解析

- **RES-001** 自有内容解析为站内阅读地址。
- **RES-002** 第三方资料解析为上游网页地址；没有上游地址时返回 `unavailable`。
- **RES-003** 云端代码不读取、探测或假设存在 `local-courses/`。
- **RES-004** 云端不提供任意 URL 的服务端抓取或代理接口。

### 8.3 本地解析

- **RES-005** 白名单内且实际存在的本地文件解析为站内本地阅读地址。
- **RES-006** 本地文件不存在时，有上游地址的条目回退为 `external-link`。
- **RES-007** 本地文件不存在且无上游地址时返回 `unavailable`，页面显示原因。
- **RES-008** 解析后的路径必须位于配置的只读挂载根目录内。
- **RES-009** 拒绝绝对路径、空字节、符号链接逃逸和 `..` 路径穿越。
- **RES-010** 云端与本地 adapter 实现同一个 Content Resolver 接口。

## 9. 阅读器规格

- **READ-001** 支持 Markdown、GFM 表格、代码块、图片、标题目录和上下章导航。
- **READ-002** 保存并恢复最近阅读位置。
- **READ-003** 阅读位置变化不得自动把条目标记为完成。
- **READ-004** 渲染采用标签与属性白名单。
- **READ-005** 禁止脚本、事件属性、任意 iframe 和可执行 MDX JavaScript。
- **READ-006** 无法安全渲染的本地内容提供纯源码视图和上游链接。
- **READ-007** 图片路径与文档路径受同一根目录约束。
- **READ-008** 素材目录只读挂载，阅读器不修改素材文件。
- **READ-009** 第三方 Markdown 中的排版 HTML（居中容器、徽章、`<br>`、表格、`<details>`）按 READ-004 的白名单保留，不转义成可见文本；`&emsp;` 等有效字符实体原样输出。
- **READ-010** 未在课程条目中声明的图片整个丢弃，不渲染为损坏图片。放宽图片白名单属于安全边界变更，需先更新 ADR。
- **READ-011** 目录与正文并列显示并跟随滚动；长目录内部滚动，不把正文挤窄。
- **READ-012** 上下章导航是显式控件；首章无上一章、末章无下一章，两端不指向不存在的章节。
- **READ-013** 正文中的相对链接按当前文档所在目录解析：命中允许章节时改写为站内阅读地址，否则降级为纯文本。不得输出会被解析到阅读器路由下的相对地址。
- **READ-014** 允许阅读的章节由课程条目声明；未声明的素材文件不可读，界面不给出指向它的可点击入口。

## 10. 学习状态规格

### 10.1 状态模型

条目状态：`not_started → in_progress → completed`。

- **STATE-001** 打开站内正文或点击外部资料时，条目可标记为 `in_progress`。
- **STATE-002** 条目只能由用户主动标记为 `completed`。
- **STATE-003** 用户可以把已完成条目改回进行中或未开始。
- **STATE-004** 阶段的普通任务可以逐项勾选。
- **STATE-005** 阶段必须至少关联一条成果记录，并由用户主动确认后才算完成。
- **STATE-006** 成果记录支持 GitHub 仓库、演示链接或 Markdown 学习总结。
- **STATE-007** 用户可以收藏或取消收藏条目。
- **STATE-008** 用户可以为条目或阶段创建、编辑和删除私人 Markdown 笔记。
- **STATE-009** 学习面板提供继续阅读入口和最近活动。
- **STATE-010** 云端用户状态在不同会话中保持一致。
- **STATE-011** 本地用户状态在容器重启后保持一致。

### 10.2 数据表边界

| 数据域             | 表                              |
| ------------------ | ------------------------------- |
| 身份与会话         | `users`、`accounts`、`sessions` |
| 条目进度与阅读位置 | `item_progress`                 |
| 阶段任务           | `stage_task_progress`           |
| 私人笔记           | `notes`                         |
| 收藏               | `bookmarks`                     |
| 阶段成果           | `stage_outcomes`                |
| 运营聚合           | `operational_metrics`           |
| 迁移记录           | `schema_migrations`             |

数据库用迁移管理；删除用户时级联删除全部个人状态。`operational_metrics` 只保存按时间桶聚合的事件类型、范围、结果和数量，不关联用户 ID、IP、Cookie、查询参数、笔记正文、路径参数或秘密，并有有限保留期。

## 11. 搜索规格

- **SEARCH-001** 云端索引阶段、课程元数据、自有正文和项目内容。
- **SEARCH-002** 本地模式额外索引内容目录白名单内的本地章节。
- **SEARCH-003** 不递归扫描整个 `local-courses/`。
- **SEARCH-004** 结果标记内容类型、阶段、轨道和访问方式。
- **SEARCH-005** 结果遵循 Content Resolver 的当前解析结果。
- **SEARCH-006** 内容或素材更新后，索引可以重建或增量更新。
- **SEARCH-007** 索引不包含私人笔记正文。
- **SEARCH-008** 同一份可打开的文档在结果中只出现一次：单章条目的正文并入条目本身检索，只有多章条目才另外产出逐章结果。
- **SEARCH-009** 每条结果给出可区分的定位信息：有关联阶段时显示阶段，否则显示所属合集。

## 12. 素材维护规格

- **MAT-001** 网站进程只读取素材状态快照，不执行嵌套仓库更新。
- **MAT-002** 宿主机命令支持 `check`、单课程 `update`、`audit`、`reindex` 和 `drift`。
- **MAT-003** `check` 区分最新、落后、分叉、本地修改和检查失败。
- **MAT-004** `update` 一次只处理一个明确的课程 ID。
- **MAT-005** 更新只允许 fast-forward；否则停止并报告。
- **MAT-006** 有已追踪本地修改的仓库拒绝自动更新。
- **MAT-007** 更新成功后执行路径审计并刷新搜索索引。
- **MAT-008** 输出机器可读结果和便于人工查看的摘要。
- **MAT-009** 素材状态快照不包含 Git 凭据或其他秘密。
- **MAT-010** 目录漂移（Catalog Drift，目录声明与磁盘实际的偏差）可单独对账：报告失效路径及候选新位置、未收录的仓库、缺少上游回退的条目；发现问题时非零退出，且不进入 `npm run check`。它与 MAT-003 的新鲜度检查是两件事。
- **MAT-011** 漂移修复只自动落盘被多条路径共同印证的目录搬迁；判不准或已删除的路径必须留给人工决定（[ADR 0007](../adr/0007-catalog-drift-is-proposed-not-applied.md)）。

## 13. 数据导出与删除规格

- **DATA-001** 用户可以导出自己的进度、阶段任务、收藏、成果和笔记。
- **DATA-002** 导出至少提供结构化 JSON；笔记另可导出为 Markdown。
- **DATA-003** 导出不包含其他用户数据、会话密钥或 OAuth Token。
- **DATA-004** 删除账户前要求明确确认。
- **DATA-005** 删除后，身份、会话和全部个人学习状态被删除。
- **DATA-006** 删除账户不修改 Git 管理的公开内容。

## 14. 管理与健康规格

- **ADMIN-001** 管理员可查看内容 schema 和引用审计结果。
- **ADMIN-002** 管理员可查看素材最新、落后、分叉、本地修改和失败状态。
- **ADMIN-003** 管理员可查看失效上游链接及最近检查时间。
- **ADMIN-004** 管理员可查看数据库、备份和部署版本健康状态。
- **ADMIN-005** 访问统计只提供不关联个人身份的汇总。
- **ADMIN-006** 管理页面不暴露环境变量、Token、数据库文件或服务器绝对路径。

## 15. 部署规格

### 15.1 通用要求

- **DEPLOY-001** 云端和本地使用同一应用代码、镜像、课程 ID、内容 schema 和学习状态模型。
- **DEPLOY-002** 镜像多阶段构建，不包含开发依赖、Git 凭据或本地素材库。
- **DEPLOY-003** Compose 提供基础配置以及云端、本地覆盖配置。
- **DEPLOY-004** 应用提供存活和就绪健康检查。
- **DEPLOY-005** 生产部署使用固定版本或 digest，不使用 `latest`。

### 15.2 云端模式

- **DEPLOY-006** `DEPLOYMENT_MODE=cloud` 时启用 GitHub 登录。
- **DEPLOY-007** SQLite 位于服务器持久化卷。
- **DEPLOY-008** 云端启动不要求挂载 `local-courses/`。
- **DEPLOY-009** 云端通过反向代理和 HTTPS 对外服务。

### 15.3 本地模式

- **DEPLOY-010** `DEPLOYMENT_MODE=local` 时默认启用本地单用户身份。
- **DEPLOY-011** `local-courses/` 以只读卷挂载。
- **DEPLOY-012** SQLite 位于本机持久化数据目录。
- **DEPLOY-013** 默认端口只绑定 `127.0.0.1`。
- **DEPLOY-014** 已存在的本地资料在断网时仍可阅读和搜索。
- **DEPLOY-015** Docker 入口可复现地选择 Local、Cloud 或已发布镜像模式，启动后验证健康接口；不得把 Local 模式暴露到非回环地址。

### 15.4 运维脚本边界

- **DEPLOY-016** 每个维护脚本归入"本机 → 本机"、"本机 → 本机 Docker"或"作用于云端"之一，并在 [docs/deploy/README.md](../deploy/README.md#脚本按运行位置分类) 登记执行位置、作用对象和硬依赖。
- **DEPLOY-017** 依赖 `local-courses/` 或浏览器的脚本不得在生产主机运行，也不进入 `npm run check`，自己以非零退出码作为独立门禁。
- **DEPLOY-018** 本机、云端手工、云端脚本三条运行路径各有一份可独立执行的 Runbook；云端两份逐步对应，脚本失败时能定位到手工流程的对应步骤。

## 16. 安全、隐私与可靠性

### 16.1 安全

- **SEC-001** 所有输入、Markdown、URL 和本地路径均需校验。
- **SEC-002** 用户写的 Markdown 不执行脚本或任意 MDX 代码。
- **SEC-003** 登录、笔记、导出和删除接口具备 CSRF 防护和频率限制。
- **SEC-004** 生产环境的会话 Cookie 使用 Secure、HttpOnly 和适当的 SameSite。
- **SEC-005** 日志不记录 OAuth Token、会话密钥、笔记正文和数据库秘密。

### 16.2 隐私

- **PRIV-001** 只保存 GitHub 身份所需的最少字段。
- **PRIV-002** GitHub Token 不用于身份登录之外的用途。
- **PRIV-003** 不接入广告型或跨站追踪。
- **PRIV-004** 私人笔记默认只有创建者可见。

### 16.3 SQLite 与备份

- **OPS-001** SQLite 主文件、WAL 和共享内存文件位于同一主机的持久化磁盘。
- **OPS-002** 启用 WAL 前验证运行时 SQLite 版本已包含 WAL-reset 问题修复。
- **OPS-003** 每日创建一致性备份，并把加密副本保存到服务器之外。
- **OPS-004** 保留最近 7 个每日备份和 3 个每周备份。
- **OPS-005** 每次生产升级前额外创建快照。
- **OPS-006** 定期执行并记录干净环境恢复演练。记录至少包含日期、耗时、主机与平台、应用版本和逐项结果。
- **OPS-007** 恢复演练是一条自带判定的命令：备份、在全新目录恢复、逐表比对行数，以退出码作为结论。它必须同时证明恢复路径会拒绝错误口令、被篡改的密文和覆盖已有目标；任何一项"本该失败却成功"都等同于演练失败。
- **OPS-008** 演练读取生产数据时只读挂载状态卷，经 SQLite 在线备份 API 取快照；不停服、不写入运行中的卷。

## 17. 可用性与质量要求

- **NFR-001** 桌面和手机端都能完成核心学习流程。
- **NFR-002** 主要导航、筛选、阅读器和表单可以用键盘操作。
- **NFR-003** 交互控件有可识别的标签；文字、焦点和状态颜色满足基本对比度要求。
- **NFR-004** JavaScript 未加载完成时，内容页仍提供可理解的主体信息。
- **NFR-005** 空状态、无结果、内容缺失、上游失效和断网时给出明确的恢复建议。
- **NFR-006** 类型检查、格式检查、单元测试、集成测试和生产构建进入 CI。
- **NFR-007** 关键流程有端到端测试：匿名浏览、登录保存状态、本地阅读、数据导出和删号。
- **NFR-008** 运行错误、登录失败、数据库健康、备份和内容审计结果可观测。
- **NFR-009** 开发服务通过 `127.0.0.1` 和 `localhost` 都能正常完成客户端加载（hydration）。
- **NFR-010** 界面走查可重复执行：desktop/tablet/mobile 三档全页截图，对 HTTP 错误、横向溢出、异常页面高度和控制台报错非零退出。依赖运行中的服务，不进入 `npm run check`。
- **NFR-011** 功能回归可重复执行并真实点击：站内链接、翻页、筛选、章节导航和学习状态的写入、读取与删除。脚本识别运行模式，对该模式不具备的能力断言其正确回退，而不是记为失败。
- **NFR-012** 端到端测试按运行模式分别成立：云端必须真实登录一次，覆盖匿名拒绝、CSRF、导出和删号后会话失效；本地直接驱动固定单用户。两者由 CI 在构建产物上按模式各跑一次，不进入 `npm run check`。测试以删号收尾，开跑前必须拒绝已有学习状态的目标，除非调用方显式声明数据可弃。

## 18. 验收场景

| 编号  | 场景             | 给定                                | 当                                       | 那么                                                                     |
| ----- | ---------------- | ----------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| AC-01 | 云端无本地素材   | 构建环境中没有 `local-courses/`     | 构建并以 cloud 模式启动                  | 构建和启动成功；公开页面可访问；第三方条目显示上游链接，无本地文件请求   |
| AC-02 | 本地优先与回退   | 以 local 模式启动，素材只读挂载     | 打开一个有本地文件的第三方条目           | 在站内阅读器打开；文件缺失时同一条目回退到上游网页                       |
| AC-03 | 路径穿越防护     | 路径含 `..`、绝对路径或逃逸符号链接 | 阅读器尝试解析                           | 请求被拒绝，不返回挂载根外的内容                                         |
| AC-04 | 学习进度保持     | GitHub 用户已登录                   | 更新进度、收藏、笔记和阅读位置后重新登录 | 状态按用户正确恢复，其他用户无法访问                                     |
| AC-05 | 阶段完成约束     | 普通任务已完成，但未提交成果        | 尝试完成阶段                             | 被拒绝并提示添加成果；添加成果并主动确认后才完成                         |
| AC-06 | 个人数据生命周期 | 用户已有学习数据                    | 导出数据，再确认删号                     | 导出含进度、任务、收藏、成果和笔记，无秘密或他人数据；删号后级联删除     |
| AC-07 | 素材更新保护     | 某嵌套仓库有本地修改或已分叉        | 执行单课程更新                           | 被拒绝并报告原因；干净且可 fast-forward 的仓库可更新并随后审计、重建索引 |
| AC-08 | 移动端完整流程   | 常见手机宽度                        | 选阶段、搜课程、读正文、写笔记、交成果   | 全流程无需切换到桌面端                                                   |
| AC-09 | 备份恢复         | 一份生产兼容的一致性备份            | 在干净服务器恢复并启动相同版本           | 身份关联和学习状态完整可读，健康检查通过                                 |
| AC-10 | 旧站能力对等     | 旧站 `learning-site/` 的能力清单    | 执行新旧功能对照                         | 新站覆盖全部首版必需能力，未覆盖项有明确的迁移决定                       |

## 19. 需求追踪规则

- 每个任务引用一个或多个需求 ID 或验收场景；每个需求至少由一个任务实现，并由自动测试、人工验收或运维演练验证。覆盖情况见 [tasks.md 需求覆盖矩阵](./tasks.md#5-需求覆盖矩阵)。
- 变更需求时同步更新 tasks.md 的任务与矩阵，以及相关测试。
- 涉及运行模式、内容归属、身份或数据库边界的变更，先新增或修订 ADR。
