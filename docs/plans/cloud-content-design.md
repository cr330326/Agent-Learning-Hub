# 云端资讯与学习设计讨论

讨论开始于 2026-11-15，按 grill-with-docs 逐项确认。用户已通过 Q16 确认完整方案。本文保留方案确认时的访谈决定与调研依据，其中“待实施、待核实”描述属于讨论时快照；后续已进入实现和本地验收。正式需求、架构和当前实施状态分别见 [spec](./spec.md#20-云端资讯与学习扩展)、[plan](./plan.md) 和 [tasks Phase 9](./tasks.md#phase-9-云端资讯与学习衔接)。

## 已确认决定

### Q1 产品定位

用户选择资讯与学习双入口。用户每天可以浏览 AI 开发精选，也可以沿现有学习路线进行系统学习。两个入口之间支持将有价值的资讯收录为学习资料。

首页双入口与页面组成见下文功能方案；资讯发布方式见 Q3，公共学习目录的收录主体与自动化边界见 Q5。

### Q2 访问人群与登录边界

用户选择公开浏览资讯与学习内容，通过 GitHub 登录后保存个人进度、收藏和笔记。该选择沿用现有项目的公开访问与个人学习状态模型。

采集记录进入公开页面的条件见 Q3。

### Q3 自动采集内容的发布方式

用户选择按信源配置发布方式。认可的来源完成去重、主题筛选和字段校验后自动发布，新来源先人工确认。该方式用于支持日常自动运行与逐步扩充信源。

“采集信源”表示网站接收内容的输入来源，其定义记录在 [CONTEXT.md](../../CONTEXT.md)。每个信源接入时配置发布方式，异常处理及飞书“同步状态”与网站发布状态的关系见下文同步和发布流程。

### Q4 云端阅读体验

用户选择站内展示中文摘要、推荐理由和出处，阅读全文或观看视频时打开原站。

该决定明确了面向读者的展示方式。后台摘要输入见 Q6，处理结果保留方式见 Q13 与数据生命周期设计。

### Q5 资讯进入公共学习目录的方式

用户选择系统推荐、维护者确认收录。系统建议适合长期学习的资讯、所属阶段和收录理由，维护者确认后将其加入公共课程目录与九阶段路线。个人收藏按 Q2 提供。

该决定延续 ADR 0006 的人工策展边界。资讯发布与公共学习目录收录的关系记录于 [ADR 0009](../adr/0009-source-publication-and-curated-learning-intake.md)，目录发布流程见 Q11。

### Q6 摘要生成的内容依据

用户允许后台读取公开原文或可获取的视频字幕，基于实际内容生成摘要。读取失败时展示已有信息，并标注摘要缺失；读者按 Q4 到原站阅读全文或观看视频。

该决定通过 [ADR 0010](../adr/0010-public-source-extraction-for-summaries.md) 调整 ADR 0002 的后台正文采集边界。原文与字幕的保留期限见 Q13，具体存储与清理规则见下文数据生命周期设计。

### Q7 每日精选的优先标准

用户选择工程实践价值优先，偏重方法、代码、评测和可复现案例，兼顾重要动态。筛选与推荐理由围绕内容对 AI 开发实践的价值展开。

例如，传播量较低但附有代码和评测的高质量 Harness Engineering 教程，可以优先于讨论度较高的一般 AI 产品新闻。评分维度与每日精选数量见下文方案，评分门槛在接入时通过真实样本校准。

### Q8 信源管理入口

用户选择网站管理后台。维护者通过管理员 GitHub 账户登录后，可以添加与停用信源、调整采集频率及发布方式、查看失败并重试。

这项能力扩展现有运维后台。信源配置归属、凭据引用与管理操作记录见下文架构。

### Q9 资讯更新与每日精选的节奏

用户选择滚动更新与每日精选日报。各信源按配置定时采集，内容完成处理并满足发布条件后滚动更新，同时每天生成一份固定精选日报，支持集中阅读与回看。

飞书来源的新增内容取决于已有任务写入表格的时间。具体采集频率、出刊时间、历史导入与迟到内容归属规则已在 Q16 确认，见下文方案。

### Q10 部署与数据存储形态

用户选择单台服务器、一套 Docker Compose、一个域名，内部运行网页与后台采集任务。资讯及信源配置存入独立资讯 SQLite 库，身份与个人学习状态位于学习状态库，课程目录由 Git 管理。

该决定接受单机容量与可用性边界，记录于 [ADR 0011](../adr/0011-single-host-with-separate-discovery-store.md)。备份恢复、任务并发与数据库写入协调见下文架构。

### Q11 公共学习目录的发布流程

用户选择后台生成 GitHub PR，由维护者审阅合并后发布。PR 包含学习资料、所属阶段和收录理由，通过仓库检查与版本发布流程上线。

后台需要展示推荐条目与对应 PR、合并和上线状态。仓库写入使用专用 GitHub App，实际权限在接入时验证。

### Q12 模型调用预算

用户选择摘要、评分等模型调用每日初始上限为人民币 5 元。达到上限后，待处理内容排队到次日；后台显示积压并允许维护者调整额度。

该数值是功能设计中的初始预算。模型价格、计费用量及实际可处理数量需要在接入时核实，预算计日时区采用 Asia/Shanghai，已随 Q16 确认。采集服务费用与服务器费用需要在部署方案中另行列明。

### Q13 原文与字幕的保留期限

用户选择生成摘要后，后台读取的原文与字幕保留 7 天，用于重试和复核。到期清理原文与字幕，继续保存摘要、来源链接和处理记录。

Q16 确认待处理和失败副本自抓取起最多保留 7 天。临时原文与字幕使用独立临时卷，持久化备份保存摘要、引用和处理记录。

### Q14 飞书记录删除后的公开内容处理

用户选择保留已发布摘要，在后台提示来源记录已删除，由维护者决定是否下架，以支持日报和收藏的回看。

此决定针对已确认删除的唯一飞书来源记录。连接失败、权限变化和视图筛选造成的暂时不可见单独处理；删除识别与多来源关联见下文同步规则。

### Q15 首次接入的历史数据处理

用户选择导入全部可获取历史记录的标题、链接和现有摘要，模型优先处理最近 30 天内容。更早的记录可以搜索、打开原站，维护者可以在后台选择补充处理。历史记录按原始发布时间归档。

“可获取历史记录”的范围取决于配置的表格、视图、信源返回范围与访问权限。导入任务需要显示已完成分页、失败位置与覆盖范围。

### Q16 整体方案与文档同步

用户选择“认可这版方案，按此同步规格和任务”。下文完整功能方案及初始参数均已确认，包括北京时间 09:00 出刊、最多 10 条、飞书每 30 分钟与公开来源每 60 分钟采集、九个飞书子表及两家公开来源、本轮资讯能力面向 Cloud Mode。正式规格、架构、任务、项目规则和 ADR 据此同步。

## 功能方案

### 1. 用户路径与页面

首页同时提供“今日发现”和“系统学习”两个明确入口。“今日发现”展示当天精选及最新动态，“系统学习”展示九阶段路线；登录用户可继续上次学习。主导航为“发现、学习路线、课程、搜索、我的学习”，管理员另有后台入口。

| 页面           | 用户获得的能力                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 发现           | 今日精选、滚动动态、历史日报；按主题、内容类型、来源和日期筛选                                   |
| 资讯详情       | 中文标题、摘要、推荐理由、原始发布时间、作者与出处、原文按钮、摘要生成状态；登录后收藏和私人笔记 |
| 主题页         | 聚合 Harness Engineering、AI Native 等方向的资讯与已收录课程，分别展示内容类型                   |
| 历史日报       | 按日期查看固定精选，访问引用的资讯；更正与撤下有状态说明                                         |
| 学习路线与课程 | 九阶段目标、课程与实践任务；展示经过 PR 发布的新增资料                                           |
| 搜索           | 明确标注资讯、课程、阶段等结果类型，每个结果指向一个可打开目标                                   |
| 我的学习       | 课程进度、资讯收藏与私人笔记、阶段成果，以及数据导出与删号                                       |
| 管理后台       | 信源、采集任务、内容审核与更正、日报、课程收录建议、PR 状态、预算与运行健康                      |

资讯卡显示摘要状态与原始时间，视频卡补充频道和时长，Skill 卡补充平台、名称及可获取的榜单指标。平台热度指标使用原平台含义与统计时间，精选推荐展示工程价值理由。列表使用现有每页 24 条分页组件，中文标签与移动端导航遵循项目规则。

### 2. 信源接入

首版提供飞书多维表格、RSS/Atom、JSON 接口、HTML 列表四类适配器。网站后台保存来源名称、类型、主题范围、访问地址、采集频率、字段映射、发布方式、启停状态和最近成功时间。凭据由服务端受控配置引用，后台展示连接状态与脱敏标识。

用户已有定时任务继续向飞书写入数据，云端后台定时读取。云端直接采集的公开来源也进入同一处理流程。部署验收需要核实已有飞书写入任务的运行位置与持续运行条件，展示“上游最后更新”和“网站最后同步”两个时间。

| Anthropic Engineering | 纳入首批公开网页来源，已核实存在工程文章列表         | Harness、评测、上下文、Agent 工具实践                |

### 3. 同步与内容身份

- 飞书记录以来源、表 ID 和记录 ID 识别，输入字段修改形成内容版本。字段映射保存字段 ID，调用依赖字段名的接口前解析当前名称，改名或类型变化在后台提示。
- 原文 URL、平台内容 ID 与来源记录建立关联。同一条原文从多个来源导入时，聚合到同一资讯并保留各来源关系。URL 规范化保留影响正文定位的参数和片段。
- 相似标题用于产生合并建议。初版由维护者确认跨原文的事件合并，确定性身份去重自动执行。
- 榜单记录映射到平台工具身份，指标作为带日期的观测值。下载量或播放量更新刷新指标；正文、描述等内容变化进入摘要更新判断。
- 每页落库与进度记录采用事务，失败后从可验证的进度恢复。增量游标在相应数据落库后推进，时间窗口保留重叠并由记录身份去重；定期完整对账发现遗漏。
- 请求失败、权限丢失、分页未完成与视图移出分别记录。来源记录缺失先标记待核对，在获得明确删除证据后按 Q14 提示维护者。
- 飞书已有“同步状态”作为来源字段保存其含义，网站另有采集、处理与发布状态。首版以读取飞书为同步方向，网站侧的审核与发布状态保存在资讯库。
- 修改后的输入先形成待处理版本，已发布摘要保留当前有效版本；自动发布来源的更新通过校验后替换，人工发布来源的更新进入待审。维护者手动更正的字段有版本与保护标记。

### 4. 内容处理与精选

```mermaid
flowchart LR
    F[飞书与公开信源] --> I[分页采集与身份去重]
    I --> N[字段归一与主题筛选]
    N --> X[原文或字幕提取]
    X --> A[中文摘要与工程价值评估]
    A --> P{信源发布方式}
    P -->|自动| V[校验后发布]
    P -->|人工| R[待审列表]
    R --> V
    V --> D[滚动资讯与每日精选]
    V --> C[学习资料推荐]
    C --> G[GitHub PR]
    G --> M[维护者合并与版本发布]
    M --> L[公共课程与学习路线]
```

主题包含 Harness Engineering、AI Native 应用、AI 编程与开发工具、Agent 架构、上下文与记忆、工具与 Skills、评测与生产实践。四条既有学习轨道继续承担课程分类，每条资讯可以关联多个资讯主题。

模型输入由已有摘要和实际获取内容组成，记录来源、内容版本、模型及提示词版本。输出通过结构校验，摘要与推荐理由能追溯输入依据；正文不足时显示“摘要待补”或“仅有来源摘要”，视频只有标题时展示标题与链接。

评分采用工程可操作性、可验证性、与目标主题的相关度、时效与影响四项，分别保存分项理由。主题相关度先做准入判断，每日精选从已发布且处理完整的条目中排序；评分阈值通过真实样本校准。已有优质摘要可复用，发生内容变化或需要补充工程价值判断时调用模型。

模型调用合并摘要、分类与一次结构化评估，按内容版本与处理版本缓存结果。需要复核的条目可人工触发第二次评估，费用计入同一预算。网页读取已生成结果，后台任务执行模型调用。

原文与字幕提取采用可访问的公开来源。链接指向登录页面、付费墙或无法提取时，进入有原因的降级状态；可公开的标题与原文链接按信源发布规则展示。每次重定向执行目标地址校验，响应有体积、时长及类型限制；外部内容作为数据交给处理器，渲染使用现有安全策略。

### 5. 日报与历史导入

每天北京时间 09:00 生成日报，默认最多 10 条，后台可调整时间和数量。达到精选条件的条目少于目标数量时按实际数量出刊，页面显示实际覆盖与最后成功采集时间。

滚动资讯在处理和审核完成后发布。日报覆盖上次出刊截止至本次截止之间新发布的合格内容，首次历史导入记录按原始日期归档。最近 30 天的导入记录优先补摘要，后续新内容优先获得预算，历史补充处理使用剩余额度并支持后台指定优先级。

同一资讯每期出现一次，跨期再次入选需要有实质内容更新和对应理由。可信原始发布时间与本站采集时间分别保存；日期缺失、无法解析或明显异常时标记“发布时间待核实”，按采集时间供后台追踪，待核实记录先进入滚动资料列表与归档候选。

固定日报保存条目顺序及当期摘要版本。管理员更正产生可追踪修订；资讯下架后，日报引用展示撤下占位，搜索与列表同步更新。用户收藏保留目标身份和状态说明。

### 6. 个人学习与课程收录

资讯具有独立稳定 ID。资讯收藏、私人笔记及显式阅读状态放在学习状态库，课程进度仍以课程 ID 关联。打开原站记录开始阅读，完成由用户主动确认。

扩展状态接口时增加明确目标类型，旧课程数据与调用方式有兼容路径，读取和写入继续校验目标存在性与权限。资讯下架后用户可以导出或删除自己的笔记，详情按撤下状态展示。导出版本演进包含资讯状态，删号级联覆盖所有新增个人数据。

课程收录建议包含学习价值、适用阶段、前置知识、原始出处和拟新增目录内容。生成 PR 时校验目录当前版本、重复 URL、稳定 ID、阶段引用和 schema；同一建议重试复用已有分支与 PR。维护者在 GitHub 审阅合并，正式发布使用固定版本。后台分别显示“建议中、PR 待审、已合并待发布、已上线、已关闭”，上线依据运行版本中实际存在的目录条目确认。

通过目标仓库专用 GitHub App 创建变更分支与 PR，配置所需 Contents 和 Pull requests 权限。普通 GitHub 登录使用现有身份权限，仓库服务凭据由后台持有。具体权限与部署状态读取范围在接入时验证。[GitHub PR 接口](https://docs.github.com/en/rest/pulls/pulls#create-a-pull-request) · [GitHub App 安装令牌](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)

### 8. 数据、任务与预算

| 归属            | 拟保存的数据                                                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Git 课程内容    | 课程目录、阶段、任务、公开策展文章                                                                                                     |
| 学习状态 SQLite | 用户与会话、课程进度、资讯阅读状态、收藏、私人笔记和成果                                                                               |
| 资讯 SQLite     | 信源配置与映射、输入记录及版本、资讯元数据与摘要版本、来源关联、主题、指标观测、发布状态、日报、收录建议、任务、调用回执与管理操作记录 |
| 临时提取存储    | 公开网页正文、字幕及处理所需临时材料，按 Q13 清理                                                                                      |
| 服务端秘密配置  | 飞书凭据、GitHub App 凭据、模型凭据及必要的加密密钥                                                                                    |

后台任务使用资讯 SQLite 中的持久化队列，任务有唯一键、租约、心跳、重试时间与阶段结果。单个 worker 调度，数据库事务保持短小，网络与模型调用在事务外执行；崩溃恢复时已完成阶段可复用。重复点击、调度重入与并发手动操作需要幂等校验。

模型调用前按输入量、最大输出量和已配置价格预留预算，完成后按用量核销。¥5/天同时考虑已用与在途预留，额度耗尽的任务进入“等待预算”。供应商结果不明确的调用保留回执并等待核对，重试优先使用已保存结果。币种换算与价格版本写入回执，价格缺失时展示待配置状态。外部抓取付费服务若后续启用，设置独立预算并在后台列明。

时区采用 Asia/Shanghai，预算每日零点更新。已成功生成摘要的原文与字幕按 Q13 保留 7 天；待处理或失败的提取副本自抓取起最多保留 7 天，到期后按需要重新获取。重新获取内容形成新版本，避免混用不同时间的依据。

临时原文与字幕放在独立临时卷，由统一到期任务清理。持久化备份覆盖摘要、引用、处理记录和两个数据库，临时卷使用单独的生命周期配置。恢复时执行到期检查。数据库分别通过在线备份 API 生成快照，共同记录恢复批次与版本；恢复后核对个人资讯引用、任务租约、调用回执和目录发布状态。

两个数据库间的资讯 ID 关联通过应用层维护，下架使用稳定身份与状态，确保收藏和笔记可解析。用户删除操作在学习状态库内完成，个人数据导出覆盖新旧目标类型。

### 9. 单域名部署

同一 Docker Compose 启动反向代理、Next.js 网页服务和后台 worker，网页与 worker 使用同一固定版本构建产物。两个 SQLite 库与临时提取内容使用明确的本机卷路径，反向代理提供 HTTPS，浏览器访问统一域名。后台任务的健康与页面健康分别检测。

启动前配置域名与 DNS、TLS、GitHub 登录、管理员 ID、模型服务、飞书 API 身份、GitHub App 与持久化备份。模型和飞书凭据的提供方式在部署配置中说明，密钥通过服务端秘密配置交付。

本轮资讯采集与管理功能运行于 Cloud Mode，Local Mode 提供既有本地学习体验。新导航与路由按运行模式处理，双模式验收同时覆盖云端资讯功能与本地学习流程，公共状态模型的演进覆盖既有数据兼容。模式范围已随 Q16 确认。

### R1 数据库范围及用户澄清

用户最初选择了“取消资讯内容落库，保留登录、收藏、笔记和学习进度”。随后明确澄清，重点是从现有每日更新的飞书和 GitHub 取得数据，网站以飞书为主，聚合展示和跳转原链接，并请 Agent 设计合理的数据库。此前将目标解释为取消资讯持久化过于狭窄，[ADR 0012](../adr/0012-source-backed-discovery-with-personal-state.md) 已撤回该限制。

### 建议的聚合存储与更新方式（待确认）
