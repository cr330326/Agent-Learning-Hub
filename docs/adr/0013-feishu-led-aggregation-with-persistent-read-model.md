# 飞书主导的信息聚合与持久化读取数据

用户已澄清，现有定时任务每日更新飞书多维表格和 GitHub，网站以飞书为主要信源，提供信息聚合、原始链接跳转和聚合学习。网站的数据更新需跟随这些信源，数据库设计由本轮补充访谈继续明确。

建议沿用 [ADR 0011](./0011-single-host-with-separate-discovery-store.md) 的两个 SQLite 库。资讯库存储规范化的标题、源摘要、作者、链接、类型、时间、平台指标、来源关联、内容版本和同步进度，支持分页、搜索、去重与同步失败期间继续展示最近成功的数据；学习状态库存储身份、收藏、笔记和学习进度。后台定时拉取飞书及获授权的 GitHub 数据，网站页面从聚合库读取。

内容更新以源记录身份和内容摘要值做幂等判断，内容引用使用稳定条目 ID。同一链接出现于多个信源时保留来源关系，飞书提供主要展示字段，GitHub 可提供额外条目与缺失字段。URL 修订和条目合并须保持个人引用可解析。完整分页成功后才能对账，权限、网络或分页失败时保留最近成功展示数据并记录独立错误状态。

用户已确认约 5 分钟发现上游更新，页面自动刷新。后台以每 5 分钟检查一次作为首轮参数，页面显示最近同步时间；接口响应与分页同步耗时计入实际延迟。

用户已确认 openspace 聚合采集结果文件中的资料链接，作为飞书的补充信源，按明确的数据文件范围读取标题、已有摘要与原始链接。

本决定记录用户确认的聚合存储方案，[ADR 0012](./0012-source-backed-discovery-with-personal-state.md) 已按用户澄清撤回。用户已确认整体方案，首轮使用来源已有内容完成聚合展示，模型增强与固定日报沿用各自处理规则。实施及验收见任务 T9.10。
