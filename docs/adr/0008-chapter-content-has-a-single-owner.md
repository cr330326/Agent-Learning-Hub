# 章节正文只有一个目录拥有者，退场条目用 redirect 保持旧 ID 可解析

目录里同一份本地素材文件曾经被多个条目同时声明。旧站导入把每个上游章节文件都升格成了独立条目(`legacy-reading-*`,共 472 个)，而 42 张课程卡的部分 `references` 又指向其中一些相同的文件。2026-08-25 盘点：514 个条目里 74 个声明路径被重复拥有——73 个是课程卡与单章条目重叠，1 个是两个单章条目重叠；涉及 38 张课程卡和 82 个单章条目。

重复拥有不是纸面问题。`buildRuntimeSearchIndex()` 给多章条目产出逐章文档、把单章条目的正文折叠进条目文档，于是同一段正文在搜索里出现两行，指向两个不同的 URL——直接违反「一条结果只代表一个可打开的目标」。

## Decision

**一份本地素材正文的完整检索与阅读归属，只能属于一个未退场条目。**

- 多章课程卡(`legacy-course-*`)声明的主线章节由课程卡拥有：逐章文档、上下章翻页、正文内链都在课程卡的阅读器里，保留课程语境。
- 与课程卡章节重叠的单章条目退场：条目保留在目录中并携带 `redirect` 字段,旧 ID(`/courses/<id>`、`/read/<id>``)永久解析到拥有者的对应位置——章节重定向进拥有者的阅读器(`/read/<owner>?chapter=<path>`),保住课程语境;其余重定向到拥有者的课程导览。条目数据本身保留,以维持 IA-004 的 ID 稳定与云端/本地一致。
- 唯一归属由 schema 强制：`contentCatalogSchema` 拒绝「同一路径被多个未退场条目声明」「redirect 指向不存在的条目」「redirect 章节未被目标声明」「阶段阅读列表引用已退场条目」。违反即构建、审计、启动全部失败——这是目录内部一致性,和重复 stable ID 同级,不属于 Catalog Drift 的"另报不挡门禁"。
- 退场条目不作为归属方计数,所以它和拥有者共存是合法的。

**唯一的例外是一次人工裁决**:`Agentic/openchamber/README.md` 同时是生态卡 `legacy-course-018` 的一条 reference 和专用卡 `legacy-course-033` 的正文。裁决为后者拥有;前者移除这条 reference——集合卡的职责是路由,专用卡已是第一入口。`Agentic/Harness/deepagents/AGENTS.md` 的两个单章条目重叠,保留标题更具描述性的 `legacy-reading-31-008`(「DeepAgents 工程约定」),另一个退场。

## Rejected alternatives

- **从课程卡移除重复 references(单章条目拥有正文)。** 课程卡的阅读器会失去这些章节的翻页与目录,README 正文里的相对链接会因不再被条目声明而降级为纯文本——T8.7 修复的「打开了第一章却点不到下一章」会回归。与 T8.8「主线课程在站内可连续读到完整章节」的目标相反。
- **只在搜索索引层按路径去重,目录保持重复声明。** 标题匹配仍会双行;目录里同一内容继续以两张卡出现;每个后来者都要重新理解"为什么不重"。去重逻辑放在数据层之后,索引层就不需要任何特判。
- **直接删除退场条目。** IA-004 要求 ID 稳定;本地部署已把这些 URL 交给过读者。redirect 是廉价保险。

## Consequences

- 课程目录从 514 条降到 395 条,共 119 个单章条目退场:81 个是本决策落地时被课程卡章节遮蔽的存量重复,38 个是随后的两门课程策展(AI Agent Deep Dive 16 章、Harness Books 双册 22 章)中被课程卡收编的。目录更短,每条内容只有一个入口。
- 未来为主线课程补章节声明时,声明一个已被单章条目拥有的文件仍会被 schema 拒绝——正确的做法是让该单章条目退场并 redirect 到课程卡,这正是本次建立的模式。
- 退场条目保留原有 `references`、`legacyImport` 等字段作为溯源,但不再出现在目录列表、搜索、首页计数和学习面板;`audit:content` 对它们的 `local-path-*` 检查照常进行。
- 学习状态以 itemId 记账:极少数针对旧条目的收藏/进度行仍指向 redirect 目标,打开时会被转发,不丢数据。
