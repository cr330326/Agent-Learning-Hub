# 隐私优先的运营指标只保存匿名聚合

## 状态

已采纳（2026-08-11）。

## 背景

系统需要让管理员看到页面访问汇总、请求或登录失败、数据库健康及运维结果，同时不能把
Learning State、IP、Cookie、请求原文或秘密变成分析数据。将原始请求日志交给应用保存
虽然容易实现，却会扩大个人数据边界并使删号语义不清晰。

## 决策

- 使用与 Learning State 同一 SQLite 文件中的 `operational_metrics` 记录按小时聚合的固定
  事件、固定范围、结果、计数和最后发生时间；表中没有用户外键或原始请求字段。
- 仅接受预定义的页面范围与运行事件，路径参数、查询参数、IP、Cookie、错误原文、笔记
  正文、OAuth Token、会话密钥和数据库连接信息一律不进入指标或结构化日志。
- 指标保留 30 天；管理员健康页只显示聚合计数和本地失败阈值的告警结果。日志收集与告警
  投递留给部署方的监控平台，应用不配置外部追踪或通知端点。

## 后果

运营指标不属于 Learning State，不随账户删除导出或级联删除；因此它只能保留无法反推个人
身份的汇总。未来若需要更细粒度可观测性，必须先修订该 ADR、规格和数据边界，而不能把
请求或学习数据直接写入本表。
