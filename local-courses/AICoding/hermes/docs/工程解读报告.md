## 一、项目概览

**Hermes Agent** 是由 [Nous Research](https://nousresearch.com) 构建的"自改进型 AI 智能体"，也是目前唯一具备内置学习循环的 Agent 系统。它能够从经验中创建技能、在使用中持续改进、主动将知识持久化、搜索历史对话，并在多会话间构建对用户的深度认知模型。

### 1.1 核心定位

- **自改进学习闭环**：Agent 创建的技能会被自动管理（Curator 系统），根据使用频率自动归档或优化
- **多平台统一入口**：Telegram、Discord、Slack、WhatsApp、Signal、Email、Matrix、Teams 等 15+ 消息平台，全部通过单一 Gateway 进程服务
- **任意模型后端**：支持 OpenRouter（200+ 模型）、Nous Portal、Anthropic、OpenAI、Gemini、DeepSeek、Kimi、Bedrock、NVIDIA NIM 等 30+ 推理后端
- **七种终端后端**：本地、Docker、SSH、Singularity、Modal、Daytona、Vercel Sandbox，支持从 $5 VPS 到 GPU 集群的弹性部署
- **研究就绪**：内置批处理轨迹生成、Atropos RL 训练环境、轨迹压缩，可直接用于训练下一代工具调用模型

## 三、整体架构

Hermes Agent 采用**分层模块化架构**，核心设计原则包括：

1. **自注册机制**：工具、Provider、平台适配器通过模块级注册自动发现，无需维护中央导入列表
2. **纯数据驱动**：皮肤/主题、技能、配置均通过 YAML/Markdown 定义，不修改代码即可扩展
3. **插件不可侵入核心**：插件只能通过框架暴露的钩子扩展，禁止修改 `run_agent.py`、`cli.py` 等核心文件
4. **跨平台安全**：Windows、macOS、Linux、Termux(Android) 均为一等公民，避免 POSIX-only 原语

### 3.2 关键数据流

1. **CLI 模式**：`hermes_cli/main.py` → `HermesCLI` (`cli.py`) → `AIAgent` (`run_agent.py`) → `model_tools.py` → `tools/registry.py`

## 四、核心模块详解

### 4.1 AIAgent 核心循环 (`run_agent.py`)

`run_agent.py` 是整个项目的"大脑"，包含 `AIAgent` 类，约 **15,700 行代码**。

**核心特征：**
- **完全同步的主循环**：`while` 循环内调用 `client.chat.completions.create()`，处理 `tool_calls`，累积消息历史
- **预算与中断控制**：`iteration_budget` 跟踪 API 调用成本，`_interrupt_requested` 支持用户中断
- **优雅调用**：即使预算耗尽，也保留一次 "grace call" 让模型有机会总结并优雅退出
- ** reasoning 内容存储**：模型思考过程保存在 `assistant_msg["reasoning"]` 中
- **懒加载 SDK**：OpenAI/Anthropic/boto3 等重型库通过代理对象延迟导入
- **上下文压缩**：集成 `ContextCompressor`，当窗口接近上限时自动压缩中间轮次，保护头部（系统提示）和尾部（最近对话）

**简化版循环伪代码：**
```python
while (api_call_count < max_iterations and budget.remaining > 0) or grace_call:
    if interrupt_requested: break
    response = client.chat.completions.create(model=model, messages=messages, tools=tool_schemas)
    if response.tool_calls:
        for tc in response.tool_calls:
            result = handle_function_call(tc.name, tc.args, task_id)
            messages.append(tool_result_message(result))
        api_call_count += 1
    else:
        return response.content
```

### 4.2 工具系统 (`tools/`)

工具系统采用**自注册 + 自动发现**机制：

1. **注册**：每个工具文件在模块级别调用 `registry.register(...)`
2. **发现**：`model_tools.py` 导入 `registry` 时触发 AST 扫描，自动导入所有 `tools/*.py`
3. **暴露**：只有被加入 `toolsets.py` 中某个 toolset 的工具才会被 Agent 看到
4. **可用性检查**：每个工具可定义 `check_fn`（如检查环境变量是否存在），运行时动态过滤

**关键组件：**

| 文件 | 职责 |
|------|------|
| `tools/registry.py` | `ToolRegistry` 单例，线程安全，支持代际计数缓存失效 |
| `tools/model_tools.py` | 编排层，连接 Agent 与 Registry，维护持久事件循环防止 `asyncio` 死锁 |
| `tools/toolsets.py` | 定义 `_HERMES_CORE_TOOLS` 和 `TOOLSETS` 字典，控制平台暴露的工具集 |
| `tools/terminal_tool.py` | 终端执行入口，支持前台/后台任务、sudo 密码注入、复合命令重写 |
| `tools/environments/` | 7 种终端后端统一抽象：`BaseEnvironment` → local/docker/ssh/modal/daytona/singularity/vercel |
| `tools/delegate_tool.py` | 子代理委派，支持单任务和批量并行（`ThreadPoolExecutor`），带深度与并发上限 |
| `tools/browser_tool.py` | 浏览器自动化，支持 Browser Use 云、Browserbase、本地 Chromium CDP |
| `tools/file_tools.py` | 文件读写、Patch、搜索，大文件/模式操作走 `ShellFileOperations` |
| `tools/approval.py` | 危险命令审批队列，支持 per-session 的允许/拒绝/始终允许 |

### 4.3 Provider 适配层 (`agent/transports/`)

所有 LLM Provider 的差异化逻辑被隔离在 Transport 适配器中，核心循环只看到标准化的 `NormalizedResponse` 和 `ToolCall`。

**已有适配器：**
- `anthropic_adapter.py` — Messages API，支持 thinking budget、adaptive effort
- `bedrock_adapter.py` — AWS Bedrock Converse API，IAM/SSO 凭证链
- `codex_responses_adapter.py` — OpenAI Responses API（Codex），处理 `to=functions.*` 泄漏
- `gemini_native_adapter.py` / `gemini_cloudcode_adapter.py` — Google Gemini
- `openai_adapter.py` — 标准 OpenAI 兼容接口

**插件化 Provider：** `plugins/model-providers/` 目录下 30+ 后端（OpenRouter、DeepSeek、Kimi、MiniMax 等），通过 `register_provider(ProviderProfile(...))` 自注册，用户插件可覆盖内置同名 Provider。

### 4.4 记忆系统 (`agent/memory_manager.py` + `plugins/memory/`)

- **内置记忆**：`tools/memory_tool.py` 管理 `MEMORY.md` / `USER.md` 文件式记忆
- **插件记忆**：8+ 可选后端（Honcho、mem0、supermemory、hindsight、holographic 等），通过 `MemoryProvider` ABC 接入
- **生命周期**：每轮对话前 `prefetch(query)` 注入上下文，对话后 `sync_turn(turn_messages)` 持久化
- **流式安全**：`StreamingContextScrubber` 状态机负责在流式输出中安全剥离 `<memory-context>` 标签

### 4.5 消息网关 (`gateway/`)

Gateway 是 Hermes 的多平台消息中枢，约 **16,000 行代码**。

**核心设计：**
- **适配器模式**：所有平台继承 `BasePlatformAdapter`，产出标准化的 `MessageEvent`
- **每会话 Agent 缓存**：LRU（最大 128）+ 空闲 TTL（1 小时），防止长期运行网关的内存泄漏
- **媒体缓存**：图片/音频/视频/文档下载到 `~/.hermes/cache/`，供 vision/STT 工具使用本地路径
- **交付路由**：`DeliveryRouter` 支持 `origin`、`local`、`telegram:chat_id:thread_id` 等目标格式，Cron 输出可投递到任意平台
- **Hook 系统**：`gateway/hooks.py` 支持事件驱动扩展（`gateway:startup`、`session:start`、`command:*`），从 `~/.hermes/hooks/` 加载

**支持平台：** Telegram、Discord、Slack、WhatsApp、Signal、Matrix、Mattermost、Email、SMS、Home Assistant、DingTalk、WeCom、Weixin、Feishu、QQBot、Yuanbao、BlueBubbles、Webhook、API Server 等。

### 4.6 CLI 系统 (`hermes_cli/`)

CLI 是 Hermes 的"瑞士军刀"，约 **12,000 行命令调度代码** + **13,500 行交互逻辑**。

**关键设计：**
- **单一命令真相源**：`hermes_cli/commands.py` 中的 `COMMAND_REGISTRY` 列表是 CLI、Gateway、Telegram BotCommands、Slack 子命令、自动补全的共同来源
- **三套配置加载器**：`load_cli_config()`（交互模式）、`load_config()`（子命令）、直接 YAML 加载（Gateway 运行时）
- **皮肤引擎**：`hermes_cli/skin_engine.py` 纯数据驱动主题，内置 `default`、`ares`、`mono`、`slate`，用户可放 `~/.hermes/skins/*.yaml`
- **KawaiiSpinner**：`agent/display.py` 中定义的动画等待指示器，支持皮肤自定义表情和动词

## 五、前端与交互层

### 5.1 TUI (`ui-tui/`)

- **进程模型**：`hermes --tui` 启动 Node.js Ink 进程，Ink 再 spawn Python `tui_gateway.entry`，两者通过 **stdio JSON-RPC** 通信
- **双模传输**：默认 spawn 模式；Attach 模式通过 `HERMES_TUI_GATEWAY_URL` 连接现有 Gateway（Dashboard 用）
- **状态管理**：nanostores (`$uiState`、`$overlayState`) + `useMainApp` hook
- **渲染**：助手输出支持原始 ANSI 或 Markdown-to-Ink 渲染，长对话使用虚拟滚动
- **本地命令**：`/quit`、`/clear`、`/copy`、`/paste` 等由 Ink 本地处理；其余通过 `slash.exec` 发送到 Python 后端

### 5.2 Web Dashboard (`web/`)

- **架构**：Vite + React 19 SPA，Tailwind CSS v4 暗色主题
- **核心页面**：`/chat` 页是**持久化**的——即使切换导航栏标签，xterm.js 实例、WebSocket、PTY 子进程也不会销毁，只是 `display:none` 隐藏
- **TUI 嵌入**：使用 xterm.js + WebGL 渲染器 + `@xterm/addon-fit`，通过 WebSocket PTY 连接后端，后端 spawn 真实的 `hermes --tui` 子进程
- **插件系统**：Dashboard 插件可注册导航标签、覆盖路由，通过 manifest JSON 声明，支持 `backdrop`、`header-left`、`chat:top` 等插槽注入
- **侧边栏事件**：PTY 子 Gateway 可打开 back-WS 将工具/推理/状态事件镜像到 Dashboard 侧边栏 (`ChatSidebar`)

### 5.3 ACP IDE 适配 (`acp_adapter/`)

- **协议**：Agent Client Protocol (ACP)，stdio JSON-RPC
- **集成**：VS Code、Zed、JetBrains 等 IDE
- **能力**：会话 CRUD、提示词处理、工具调用、MCP 服务器注册、审批桥接
- **工具映射**：Hermes 工具映射为 ACP `ToolKind`（`read`、`edit`、`execute`、`fetch`、`think` 等）

## 六、扩展系统

### 6.1 插件系统 (`plugins/`)

Hermes 拥有**多个独立的插件表面**，各自通过不同的发现机制接入：

| 插件类型 | 发现机制 | 代表插件 |
|---------|---------|---------|

| 模型提供者 | `providers._discover_providers()`（首次使用时） | `openrouter`、`anthropic`、`gemini`、`deepseek` 等 30+ |

| 图像生成 | `agent/image_gen_provider.py` | `openai`、`openai-codex`、`xai` |
| 上下文引擎 | `agent/context_engine.py` | 可插拔上下文管理（如 LCM） |
| 网关平台 | `gateway/platform_registry.py` | `google_chat`、`irc`、`line`、`teams` |

**插件规范**：每个插件目录包含 `__init__.py` + `plugin.yaml`，声明 `kind`、`version`、`pip_dependencies`、`hooks`。插件**禁止修改核心文件**，需要新能力时应扩展通用框架表面。

### 6.2 技能系统 (`skills/` + `optional-skills/`)

- **内置技能**（`skills/`）：~729 文件，默认加载。覆盖软件开发（TDD、调试、计划撰写）、创意（ASCII 艺术、Manim、ComfyUI）、研究（Arxiv、LaTeX 论文模板）、DevOps（Kanban、Webhook）、MLOps（vLLM、llama.cpp、Axolotl）等
- **可选技能**（`optional-skills/`）：~423 文件，需手动安装。覆盖区块链（Base、Solana）、金融（DCF、LBO）、健康、安全（1Password、取证）、Web 开发等
- **格式**：每个技能一个目录，核心为 `SKILL.md`，含 YAML frontmatter（`name`、`description`、`version`、`platforms`、`metadata.hermes.tags`）
- **使用方式**：技能内容被注入系统提示词，Agent 通过加载 `SKILL.md` "调用"技能
- **生命周期**：Agent 创建的技能受 Curator 管理，根据使用频率自动归档/优化；官方技能不可被 Curator 修改

### 7.2 测试基础设施 (`tests/conftest.py`)

- **凭证隔离**：自动剥离所有 `_API_KEY`、`_TOKEN` 环境变量，防止测试误调真实 API
- **Hermes Home 隔离**：每个测试使用独立的 `tmp_path` 作为 `HERMES_HOME`
- **确定性环境**：强制 `TZ=UTC`、`LANG=C.UTF-8`、`PYTHONHASHSEED=0`
- **模块级状态重置**：审批队列、中断标志、ContextVars、工具注册表、终端环境在每测试间重置
- **活体保护**：拦截 `os.kill`、`subprocess.*`、`systemctl`，防止测试杀死开发者真实的 `hermes-gateway` 进程
- **超时保护**：每测试 30 秒 SIGALRM 超时

### 8.1 部署方式

### 8.2 关键运维特性

## 十、总结

Hermes Agent 是一个**架构设计极其成熟、工程实践非常到位**的大型开源 AI Agent 平台。其核心竞争力不仅在于支持多模型、多平台、多终端的"广度"，更在于以下"深度"：

1. **自改进学习闭环**：Curator 系统管理 Agent 创建的技能，使 Agent 具备真正的持续学习能力
2. **统一抽象层**：Transport、Environment、MemoryProvider、PlatformAdapter 等 ABC 设计，让新增 Provider/后端/平台成为"填空题"
3. **安全与隔离**：审批系统、凭证脱敏、Windows 安全扫描、活体保护测试、供应链审计，工程安全意识极高
4. **全链路覆盖**：从终端 TUI 到 Web Dashboard，从 IDE ACP 到消息网关，从本地 CLI 到 Docker 部署，从个人使用到批处理 RL 训练，全场景覆盖

**适合的学习路径**：
- 理解核心循环 → 从 `run_agent.py` 的 `run_conversation()` 开始
- 理解工具系统 → 从 `tools/registry.py` 的自注册机制入手
- 理解扩展机制 → 从 `plugins/model-providers/openrouter/` 或 `plugins/memory/honcho/` 看插件范例
- 理解网关架构 → 从 `gateway/platforms/base.py` 的 `BasePlatformAdapter` 和 `gateway/run.py` 的缓存策略入手
- 理解前端嵌入 → 从 `ui-tui/src/gatewayClient.ts` 的 JSON-RPC 和 `web/src/pages/ChatPage.tsx` 的 xterm.js PTY 入手
