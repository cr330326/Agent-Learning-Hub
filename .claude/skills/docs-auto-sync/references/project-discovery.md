# Project Discovery

用本指南发现仓库自己的文档体系。不要把候选文件名当作必需文件。

## 1. 读取适用规则

从目标文件所在目录向仓库根目录查找并读取适用的代理或贡献规则，例如：

- `AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING.md` 及目录级同类文件；
- `.github/`、`.gitlab/`、`.config/` 或项目自定义目录中的贡献、发布和文档规范；
- skill、脚本或生成器旁边的局部说明。

更深目录的规则通常只约束该子树；若规则冲突，遵守项目声明的优先级，并向用户暴露无法消解的冲突。

## 2. 建立仓库地图

优先使用 `scripts/collect-facts.sh`，再按需要搜索。识别以下角色，而不是固定路径：

| 角色 | 常见信号 | 要确认的问题 |
| --- | --- | --- |
| 导览文档 | README、overview、getting-started | 面向谁，是否只应链接到详细事实源 |
| 产品或行为规格 | spec、requirements、PRD、RFC | 描述应有行为还是当前实现 |
| 技术决策 | ADR、decisions、RFC 状态 | 是否已接受，是否允许直接改写历史 |
| 接口契约 | OpenAPI、AsyncAPI、GraphQL schema、proto、类型契约 | 哪份是生成源，哪些是派生物 |
| 数据事实 | schema、migration、model 定义 | migration、声明式 schema 或数据库谁是权威 |
| 操作事实 | runbook、deploy、operations、Makefile、任务脚本 | 命令是否仍存在，适用环境是什么 |
| 执行状态 | tasks、roadmap、issue/PR 引用 | 谁有权改变完成状态 |
| 发布事实 | changelog、release notes、版本文件 | 是否生成，什么变化值得记录 |
| 领域语言 | glossary、terminology、domain docs | 是否有规范词和禁用词 |

## 3. 确定本次同步边界

从用户请求和实际 diff 出发，只纳入直接消费者：

- 命令或目录变化：核对快速开始、贡献指南、运行手册和 CI 文档。
- 公共接口变化：核对契约源、API 文档、示例和客户端说明。
- 配置变化：核对配置参考、示例环境文件、部署/排障文档；绝不复制真实秘密。
- schema 或 migration 变化：核对数据模型说明、图、恢复说明和兼容性记录。
- 用户可见行为变化：核对规格、使用文档和项目定义的发布记录。
- 仅内部重构且公共行为不变：通常只需核对架构/贡献文档，可能无需文档 diff。

如果用户只说“同步文档”，先检查工作区和近期变更，再扩大到仓库定义的主要导览与事实源；不要无条件重写全部文档。

## 4. 识别生成文件

搜索 `generated`、`autogenerated`、`do not edit`、`由 ... 生成` 等标记，以及 manifest、Makefile、CI 中的文档生成命令。修改生成源并运行已有生成器；若无法安全运行，保留派生文件并报告所需命令或阻塞。

## 5. 停止条件

出现以下情况时停止自动修改并报告：

- 无法判断哪个来源对某个主题有权威性；
- 需要新增或推翻需求、ADR、公共承诺或合规政策；
- 目标文档包含与当前任务重叠且无法保留的用户改动；
- 唯一验证方式会写入生产、发布制品或外部系统；
- 需要把未知值、秘密或真实数据写进文档才能继续。
