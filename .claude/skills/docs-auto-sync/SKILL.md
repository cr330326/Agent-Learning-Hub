# Repository Documentation Sync

以仓库自己的规则和证据为准，维护文档与当前实现的一致性。不要假设固定目录、技术栈、文档名称或发布流程。

## Quick Routing

| 当前需要 | 下一步 | 产出 |
| --- | --- | --- |
| 第一次进入仓库或目录结构陌生 | 读取项目发现指南 | 候选规则文件、事实源、派生文档和验证命令 |
| 代码、规格、ADR 与运行手册互相冲突 | 读取权威与变更策略 | 按主题划分的权威关系和允许修改范围 |
| 需要可重复的仓库快照 | 运行事实采集脚本 | 工作区、文档、清单、变更和契约入口摘要 |
| 需要检查仓库内 Markdown 链接 | 运行链接检查脚本 | 无效相对路径清单 |
| 需要一致的交付说明 | 使用同步报告模板 | 证据、修改、验证和未决冲突摘要 |

## Contract References

当项目布局、文档名称、技术栈或本地规则尚不清楚时：
-> Load `references/project-discovery.md` for discovery order, search heuristics, and scope selection.

当多个来源对同一事实给出不同答案，或需要判断哪些文件可以修改时：
-> Load `references/authority-and-change-policy.md` for authority mapping, conflict handling, and mutation boundaries.

当需要采集只读证据时：
-> Load `scripts/collect-facts.sh` for supported arguments and the deterministic repository snapshot it produces.

当需要校验 Markdown/MDX 内部链接时：
-> Load `scripts/check-doc-links.sh` for supported link types, arguments, and known limits.

当需要汇报结果或留下审计记录时：
-> Load `assets/sync-report-template.md` for the standard concise output shape.

## Workflow

1. **确认范围并保护现有工作。** 从仓库根目录读取适用的 `AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING*` 或同类规则文件。运行 `git status --short`，检查目标文档现有 diff；不要覆盖用户未提交的改动。
2. **发现项目自己的事实源。** 按 `references/project-discovery.md` 识别规格、决策记录、接口契约、schema/migration、运行手册、发布记录和导览文档。只有项目明确建立了某类事实源，才把它纳入同步边界。
3. **采集与本次变化相关的证据。** 优先运行本 skill 的 `scripts/collect-facts.sh`；必要时传入 `--base <ref>` 聚焦某个变更范围。
4. **建立按主题划分的权威关系。** 分别判断产品行为、架构决策、接口、数据结构、运行命令、任务状态和用户可见变更由什么文件负责；不要建立一个“所有主题都由同一文件决定”的总优先级。
5. **分类漂移。** 区分实现已变化、明确决策已变化、派生文档过期、任务状态变化和证据不足。代码能证明“现在做了什么”，不一定能证明“产品应该做什么”。
6. **只做最小文档修正。** 保留现有语气、结构、语言和链接风格。更新所有直接受影响的消费者，但不要复制完整契约、schema、枚举或操作手册来制造第二事实源。
7. **验证。** 检查目标 diff，运行项目规定的文档命令；按需运行 `check-doc-links.sh` 和 `git diff --check`。只报告实际执行过的验证，不用无关测试替代缺失证据。
8. **汇报。** 使用 `assets/sync-report-template.md`，逐项写明“文件/章节 → 修正 → 依据”，并把无法安全判断的冲突标为待确认。

## Output Guidelines

- 先给同步结果，再列验证与待确认项。
- 每项修改都指向具体实现、配置、契约、决策或用户输入；不要写“顺手更新”。
- 明确区分“已修改”“仅核对无须修改”“未修改且待确认”。
- 如果没有文档需要改动，直接说明检查范围和证据，不制造无意义 diff。
- 如果发现实现偏离规格，报告冲突；除非用户已授权，不通过改写规格来迁就实现。

## Important Rules

- 默认只修改文档及其文档专用生成产物；不修改业务代码、测试、配置、schema、migration 或部署状态。
- 不擅自改变产品需求、领域语义、已接受决策、任务完成状态、版本号或发布记录。
- 不创建项目未采用的文档体系，也不强制引入固定文件名或目录布局。
- 不把密钥、令牌、Webhook、个人信息、生产数据或本地环境值复制进文档、日志或示例。
- 不手改带有 generated、autogenerated、do not edit 等标记的文件；查找并运行其生成源或报告阻塞。
- 不执行部署、发布、数据库写入、外部消息或其他超出文档同步范围的动作。
- 若文档变更会实质改变公共契约、合规承诺或操作安全边界，暂停自动修正并请求明确决策。
