# Authority and Change Policy

按“事实主题”建立权威关系；不要假设单一文件对整个仓库拥有最高优先级。

## 主题级权威模型

| 主题 | 通常优先查看 | 实现能证明什么 | 默认同步方向 |
| --- | --- | --- | --- |
| 产品行为与范围 | 已接受规格、明确用户决策 | 当前实现行为 | 决策/规格 → 用户文档；发现偏差则报告 |
| 架构与技术选择 | 已接受 ADR/RFC、架构文档 | 实际依赖与调用结构 | 决策 + 实现 → 架构导览 |
| 公共接口 | 项目声明的契约源、兼容策略 | 实际 handler/client 行为 | 契约源 ↔ 实现核对 → 参考文档/示例 |
| 数据结构与不变量 | 项目声明的 schema 或 migration 源 | 当前持久化实现 | 数据事实源 → 模型说明与图 |
| 命令与配置 | manifest、任务脚本、配置解析器、CI | 可执行入口和当前默认值 | 实现/配置 → 快速开始与运行手册 |
| 运维与部署 | 受维护的 runbook、部署配置 | 实际自动化能力 | 配置/脚本 → runbook；生产状态需外部证据 |
| 领域术语 | 规格、词汇表、明确业务决策 | 内部标识符 | 业务决策 → 下游文档；不从变量名反推术语 |
| 任务与发布状态 | 项目任务系统、发布流程、明确授权 | 合并或未提交的实现 | 只有获授权流程才能改状态或版本 |

项目规则若明确指定不同关系，以项目规则为准。

## 差异分类

1. **派生文档过期**：权威源清楚，且文档只是在描述它。最小修正文档。
2. **实现偏离规格或决策**：不要静默改规格；报告偏差，除非用户明确选择新行为。
3. **事实源彼此冲突**：保留现状，列出冲突双方、影响和所需决策。
4. **任务或发布状态变化**：只有项目流程或用户明确授权时更新勾选、版本和发布记录。
5. **证据不足**：使用“待确认”，不要用猜测补齐命令、路径、日期、环境或兼容承诺。

## 最小修改策略

- 修改直接包含过期事实的段落；不要重排无关章节或统一全文件措辞。
- 优先链接到权威源，不在多个导览文档复制完整接口、schema、枚举、图或 runbook。
- 保留历史决策和发布记录；需要替代时新增项目规定的 superseding 记录。
- 保留示例的抽象性：使用占位符和安全默认值，不复制本机或生产环境数据。
- 公共契约、迁移兼容性、安全边界和合规承诺属于高风险文档；证据不完整时只报告，不擅改。

## 允许与禁止的动作

默认允许：读取仓库、运行只读发现/校验命令、修改文档源、运行项目已有的文档格式化和检查命令。

默认禁止：修改业务实现以配合文档、改变需求或 ADR、勾选任务、提升版本、发布、部署、写数据库、调用外部系统、手改生成产物或记录未经验证的生产状态。
